## 一、背景与本轮决定

2026-08-21 全站背景换成小程序那张浅蓝墙面（本地 `assets/images/bg02.jpg`）。当时产品说
「怕要换回去」，旧的暖白背景 `bg01.png`（1.12 MB）留在仓库里，靠 `figma_common.dart` 的一段
回滚说明认领，`unused_assets_test` 的 `parked` 白名单放行。

**2026-08-27 产品确认不会换回去** —— 图删掉，注释改口，白名单条目一并撤掉。

先复核了一遍「两端真的是同一张」再删：把小程序在用的
`https://oss.boltfox.cn/prodFile/202608211340094498724.jpg` 下下来对哈希，与
`assets/images/bg02.jpg` **sha256 完全一致**（`35f24028…`，1,016,886 字节 / 1159×2535）。
铺法也对得上：App 侧 `BoxFit.cover` ≡ 小程序 `mode="aspectFill"`。

## 二、改了什么

**删除**：`assets/images/bg01.png`（1,172,372 字节 ≈ 1.12 MiB）。`pubspec.yaml` 注册的是
`assets/images/` **整个目录**，删文件即出包，不需要动 pubspec。

**注释改口**（11 个文件）。分两类：

① **真·过期**——写着 `bg01` 而代码里其实是 `bg02.jpg`，08-21 换图时漏改的：

| 文件 | 原文 |

| `shell/presentation/splash_page.dart` | 类文档「全屏铺 `bg01.png`」+ 行内「全屏背景 bg01.png」 |
| `account/presentation/auth_widgets.dart` | 「登录/注册页全屏背景：`bg01.png` 铺满」 |
| `account/presentation/auth_page.dart` | 「闪屏和本页共用同一张背景图 bg01」 |
| `account/presentation/modify_email_page.dart` | 「全ページ共通背景 bg01」 |
| `gallery/presentation/gallery_page.dart` | 同上 |
| `home/presentation/home_page.dart` | 同上 |
| `home/presentation/home_widgets.dart` | 「全部页面统一用同一张背景 `bg01.png`」 |
| `settings/presentation/update_boltstar_page.dart` | 「走 [FigmaScreen] 默认的 `bg01.png`」 |

② **说明本身要改**：

- `shared/widgets/figma_common.dart` 的 `FigmaScreenBackground` 文档——原来那段
  「`bg01.png` 保留在仓库里（产品要求怕要换回去），要换回去把默认值和各页写死的 `bg02.jpg`
  一起改回 `bg01.png`」整段作废，改成「2026-08-27 已删除，要再换背景改这里 + 各页那几处，
  `grep -rn "assets/images/bg02.jpg" lib` 能列全」。
- `home/presentation/home_widgets.dart` 里 `home-bg03.png` 的几何说明写着
  「旧的 bg01(卡面) + bg02(投影) 两层叠加已被这一张替代」——那两个指的是
  **`home-bg01.png` / `home-bg02.png`**（08-21 清理孤儿素材时已删），与页面背景 `bg01/bg02`
  是**完全不同的两组文件**。本轮补全成带前缀的全名并加了一句「别混」。

**用例反向钉住**（`test/unused_assets_test.dart`）：

- 原「故意留着的图：认领它的注释还在」那条，判据是「`bg01.png` **必须存在** 且源码里
  **必须**还提到它」；现在反过来——`assets/images/bg01.png` **不许存在**。
  重新加回来只会又变成一张没人引用的 1.12 MB 死重量。
- ⚠️ 只钉「文件不在」，**不钉**「代码里不许提它」：`figma_common.dart` 那段
  「旧背景已删」的说明正是给下一个人看的，连注释一起禁掉等于逼人删掉这段来龙去脉。
- `parked` 白名单随之清空（原来只有 `bg01.png` 一条），并留注释说明「再往里加必须写明理由
  与认领注释在哪」。

## 三、顺带清掉 13 张无引用素材

删 `bg01.png` 时按 `unused_assets_test` 的判据（剥注释后没有任何活引用、且不在动态拼接白名单里）
复算了一遍，发现另有 **13 张孤儿图**——也就是说那条用例本来就是红的，与删 `bg01.png` 无关。
本轮**一并删掉**（31.5 KB）：

| 图 | 来路 |
| --- | --- |
| `tabbar-home01/02.svg`、`tabbar-mine01/02.svg` | 底栏图标的 **SVG 版**。⚠️ 端上活着的是**同名 `.png`**（`tabbar-home01.png` 等，四处都有活引用），**没删**；Flutter 侧没有 SVG 依赖，这四张 SVG 拷过来根本用不上 |
| `mine-icon01/02/03.png`、`mine-icon-right.png` | 「我的」页改版前的列表图标（现用的是 `mine-icon04~07`，各有活引用） |
| `radio-button-icon01/02.png`、`search-icon01.png` | 早期页面遗留 |
| `pay-wechat.png` | 支付方式图标；App 没有购买页（走 Apple IAP / Android 内购、尚未接入） |
| `device-detail-screen-size.svg` | 详情页「屏幕尺寸」行图标的**小程序原件**拷贝。App 侧那枚图标是 `_ScreenSizePainter` 按同一组坐标画出来的（没有 flutter_svg 依赖），这张 SVG 从来没有代码引用 |

其中 **11 张是当天 `b1ab4ad` 提交刚加回来的**（`mine-icon0x` / `radio-button-icon0x` /
`search-icon01` / 四张 `tabbar-*.svg`）——这批正是 08-21 那轮作为孤儿删掉的；同批 `1cc0efe`
还删掉了 `home-bg-placeholder.jpg` / `mine-bg-placeholder.jpg` **两张小程序专用的占位图**
（本来就不该在 Flutter 仓库里）。合起来像是把小程序的 `assets/images` 往这边同步过一次的痕迹。
另 2 张（`pay-wechat.png` / `device-detail-screen-size.svg`）是 `73e8016` 带进来的，
08-21 那轮的清理没覆盖到。

⚠️ **同名不同格式要分清**：`tabbar-*.png` 活着、`tabbar-*.svg` 是死的；
`mine-icon01/02/03` 死、`mine-icon04~07` 活。删之前逐个 `grep` 过整仓
（`lib` / `test` / `ios` / `android` / `web` / `windows` / `macos` / `linux` / `pubspec.yaml`），
只有上面那两处 SVG 出现在**注释**里，代码引用一处都没有。

`assets/images`：**141 个 / 3183.1 KB → 128 个 / 3151.6 KB**（含 `bg01.png` 那 1.12 MiB，
合计 −1.15 MiB）。

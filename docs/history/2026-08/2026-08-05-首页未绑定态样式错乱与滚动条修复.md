# 首页（未绑定态）在普通手机上「样式错乱 + 自己出现滚动条」修复

> 文档类型：Change Record
> 状态：Current
> 日期：2026-08-05
> 范围：Flutter APP（`_HomeMainView`：首页已绑定/未绑定两种布局的竖向结构）
> 状态说明：代码已落地并通过静态自查，**未编译、未真机**（本机无 Flutter SDK，
> 未跑 `flutter analyze` / `flutter test`）
> 对照小程序：底部 Tab 固定在滚动区外的做法与 `photo-album/pages/home` 的
> `custom-tabbar`（`position: fixed`，留在 `scroll-view` 之外）一致

## 现象

**普通手机（Android 真机、系统字体默认，不是折叠屏）** 上进首页「未绑定设备」态：
排版被挤在一起、跟设计稿对不上，页面还**自己出现了滚动**。

## 根因：本页比可用高度高几十 dp，而一旦超一点就整页降级成滚动

未绑定态是全 App 最高的一屏，按设计稿的固定尺寸从上到下排：

```text
95(留白) + 插画189 + 12 + 提示文案 + 24 + 按钮44 + 68(留白)
+ 「选择投屏方式」标题 + 8 + 投屏卡片(按屏宽等比，360dp 宽时约 148) + Spacer + Tab栏56 + 13
```

360×760dp 一类常见机型上，去掉状态栏/手势条与 44 的标题栏后可用高度约 668dp，
而上面这摞固定尺寸加起来约 696dp——**超出约 28dp**。

页面外面套的是 `SingleChildScrollView + ConstrainedBox(minHeight: 视口) + IntrinsicHeight`，
`IntrinsicHeight` 按**最大固有高度**给内容定高，而固有高度里含着 95/68 这些**纯留白**。
于是只要超出一点点，就直接触发整页降级：

- `Spacer` 被压成 0 → 元素挤成一坨（「样式错乱」）；
- 内容比视口高 → 出现滚动（「自己出现滚动条」）；
- **底部 Tab 栏排在滚动内容的末尾**，被顶到视口以外 → 得先滚一段才能点到「我的」。

留白本可以让出这 28dp，但 `IntrinsicHeight` 没有「先压留白」这个档位——它只会照着
「留白全给足」的高度定高，然后整页滚动。

## 改法

### ① 底部 Tab 栏移出滚动区（对齐小程序）

`_HomeMainView.build` 的竖向结构改为：

```text
_HomeNavBar                    ← 固定
Expanded(滚动区)               ← 只放中间内容
_HomeTabBar + SizedBox(13)     ← 固定，永远在视口内
```

`_buildBound` / `_buildUnbound` 末尾的 `_HomeTabBar` 与 `SizedBox(13)` 相应删掉，
两处保留末尾的 `Spacer()` 吃掉剩余高度——大屏观感与改动前一致（原来这段空白也在
卡片区与 Tab 栏之间），小屏则不再把 Tab 栏顶出视口。

### ② 未绑定态的两处纯留白改成「可压缩」

新增 `_CollapsibleGap`（`home_main_view.dart` 末尾，约 55 行，含一个 `RenderBox`）：

```dart
const Flexible(flex: 95, child: _CollapsibleGap(95)),   // 顶部留白
const Flexible(flex: 68, child: _CollapsibleGap(68)),   // 按钮到卡片区
```

与 `Flexible(child: SizedBox(height: 95))` 的唯一区别是**固有高度恒为 0**，这正是关键：

| 视口 | 表现 |
| --- | --- |
| 剩余空间 ≥ 两处留白之和（大屏） | 各自取到设计值 95 / 68，**与改动前逐像素一致** |
| 剩余空间不够（原本会滚动的窗口） | 两处按 95:68 的比例一起收缩，**先让留白，不滚动** |
| 留白压到 0 仍装不下（横屏/分屏/超小窗口） | 才真的滚动，兜底不变 |

`IntrinsicHeight` 因此量到的是「留白压没之后仍需要的高度」，触发滚动的门槛从
「设计稿高度」降到「内容实体高度」。360×760dp 的例子里，两处留白收缩到约 78 / 56
就正好装下，不再滚动、`Spacer` 也不再被压成 0。

已绑定态（设备轮播那版）本身余量约 100dp，固定间距一行未动，只跟着吃到 ① 的好处。

## Known Issues / Risks

- **未编译**：本机无 Flutter SDK，`flutter analyze` / `flutter test` 未跑。
  其中 `import 'package:flutter/rendering.dart';` 若被判定为多余（`material.dart` 已导出
  所需类型），`unnecessary_import` 会告警——删掉该行即可，其余代码不受影响。
- `_CollapsibleGap` 必须放在 `Flexible` 里（flex 取设计高度）才有意义：
  直接当普通子节点用会拿到无界高度约束、恒等于设计值，且固有高度记 0 会让外层量不准。
- 收缩发生在**原本就会滚动**的窗口里，所以「装得下时逐像素一致」这条成立；
  但小屏上顶部留白确实会比设计稿短一截（这是刻意的取舍：宁可留白短，也不要挤成一坨还滚动）。
- 未绑定态的提示文案若在窄屏折行成两行，会再吃掉约 16dp，收缩幅度相应变大。

# App 三十二项修复与小程序同步（2026-08-28）

> 状态：已改，⚠️ **未编译未真机**（本机无 Flutter SDK，`dart analyze` / `flutter test` 均未跑）
> 对照仓库：`/pgdata/pg/dh/photo-album`（微信小程序）
> 上一版：[2026-08-28 App 跟随系统语言](2026-08-28-App跟随系统语言.md)

本轮全部来自一次真机走查，只针对 **App 端**。下面按需求编号记，每条写清「症状 → 根因 → 改法」。

## 1. 登录/注册页「阅读协议」勾选点不中

- 症状：那个小圆点老点不中。
- 根因：视觉 16、**热区也只有 16×16**（约 2.5mm），且这一行贴在屏幕最下方、紧邻系统手势区。
- 改法（`auth_widgets.dart AuthAgreementRow`）：视觉不动，热区放大到「圆点 32×40 + 四段文案各自
  上下补 12」，整行连成一条 40 高的可点带。小程序 `.login-agreement__check-group` 用 86rpx 热区 +
  负 margin 抵消占位；Flutter 的 `Padding` 不收负值，改为
  ① 圆点右侧的 8 顶掉原来的 7 间距，② 纵向多出的 2×12 由调用页把本行前后间距各减
  `AuthAgreementRow.hitPadding`（登录页 20→8 / 16→4，注册页 16→4）抵消 —— **行的视觉位置逐像素不变**。

## 2 / 3. 微信登录中的 loading

- 3：微信图标里那颗转圈去掉（跳回 App 时它压在页面里几乎看不见，观感是「点了没反应」）。
- 2：改为盖住整页的 [AppLoadingDialog]（文案 `accWechatLoggingIn`「登录中…」），
  对齐小程序 `pages/login` 的 `login-transition` 全屏过渡层。`try/finally` 收口 ——
  登录成功后根节点会把登录页换成主壳层，跳过 hide 会让蒙层永久滞留。

## 4. 设备命名弹窗的输入框「很丑」

- 根因：全局 `AppTheme.inputDecorationTheme` 给了 `filled: true`（白底）与 `focusedBorder`
  （18 圆角 + 1.2 描边）。弹窗里只写了 `border: InputBorder.none` —— 盖不住它们
  （`enabledBorder`/`focusedBorder` 为 null 时才回落到 `border`，而主题里两者都有值）。
  表现：浅蓝胶囊里又套一块白色圆角块，且本框 `autofocus`，一打开就带一圈圆角对不齐的描边。
- 改法：`filled/fillColor/hoverColor` + 全套 border 显式关掉（同 `AuthPillTextField` 的写法）；
  占位色对齐小程序 `.name-field__placeholder` 的 `#a9b1bc`；按钮行上间距 16→15（30rpx）。

## 5. 搜索设备比小程序慢几秒

- 根因：**扫描被一次网络请求挡在前面**。`BleController.scan` 起扫前先
  `await _loadAllowedBroadcastIds()`（`getProductList` 取广播名白名单），而
  `ApiClient` 单次超时 10s、失败静默重试 2 次 —— 弱网最坏 ~30s；更糟的是**接口返回空表时不写缓存**，
  于是**每一次**扫描都要重付这笔。
- 改法：白名单不再 await。`FrameBleClient.scan` 新增 `pendingAllowedNames`：
  先用已知名单（会话缓存，否则内置 `EF6-370/EF6-589`）**立刻起扫**，产品列表在后台拉；
  回来后重算所有已收录设备的放行判定，因新名单才够格的设备**追溯性**进列表并触发一次
  `onUpdate`/`until`。并发扫描共用同一次在途请求。
- ⚠️ 另一处**没动**的耗时闸：Android「5 次起扫 / 30s」限额（`_awaitScanStartSlot`，最多等 10s）。
  超限后系统会把扫描静默降级成「整窗几乎收不到广播」，等窗口滑出是划算的。小程序天然少踩
  （一路硬件扫描多订阅者共用）。若真机上仍偶发几秒空白，下一步是把 App 也做成「共享扫描会话」。

## 6. 我的页「星币管理」行的箭头没和上下对齐

- 根因：外层 Row 是 `Expanded(标题) + Flexible(数值) + 箭头`。两个 flex 子节点各分一半余宽，
  而 `Flexible` 是 loose —— 数值只占自己那点宽，**没用完的那半不会还给标题**，
  `MainAxisAlignment.start` 把它甩到最后，箭头因此离右边缘还差二三十像素。
- 改法：外层只留一个 `Expanded` 吃满余宽（箭头必然贴右内边距，三行同一条线），
  标题与数值放进内层 `Row(spaceBetween)` 分居两端。

## 7 / 8. 星币购买：套餐列表 + 支付方式按端

- 7：星币管理页原来**根本不显示可买的 SKU**（只有一行「购买星币」入口，且 iOS 连入口都没有）。
  照小程序 `token/index` 补上「套餐购买」区：横滑套餐卡（100×124，赠送角标 / 星币数 / 售价 /
  单价，选中态橙描边 + 右上角实心角标）+ 贴底「立即购买」。后端一档都没下发时**标题恒在**，
  下面写一句「暂无可购买的套餐」，不再整块消失。
- 确认购买页随之改成小程序 `token/confirm` 的形态：**只呈现选好的那一档**（概览卡：数量 / 售价 /
  赠送 / 合计获得 / 单价），不再自己拉一遍 `getGoodsList`（同一份列表拉两次、两处各存一份选中态，
  是「选了 A 却按 B 建单」这类错的温床）。
- 8：**安卓只画 PayPal 一项；iOS 不画支付方式** —— Apple 内购未接，画一行点不动的选项更让人困惑。
  iOS 上改为一句说明（`starBuyApplePending`）+ 置灰的按钮，页面照常可进、金额照常看得见
  （需求 7「页面和交互先有，支付后接」）。iOS 不建单的闸留在 `_buy` 与 `StarPurchase.start` 两处。

## 9. 微信授权登录：后台看到的终端是苹果

- 根因：`WechatAuthorizLoginApiIn` 的 `terminal` 注释写「通过 headers 传递」，App 也确实在
  header 与 `/Client/` query 各放了一份，但**后端按 body 认端** —— body 里没有这个字段，
  于是落到 DTO 默认值。
- 改法：`terminal` / `language` / `device` 一并写进 body（它们本就是 DTO 声明的字段）。
  后端若真按 header 绑定，这份同值副本无害。用例 `wechat_login_test` 同步改成断言新 body 形状，
  「一次业务调用只发一次请求」的不变量不动。

## 11. 纯文字对话不该出现「生成图片」的 loading

- 根因：`pre_text` 一到就把渐变占位盒（生图进度条）亮出来。而服务端 2026-08-07 起
  两条路的开头**一模一样**（都先推一句「星宝努力思考中」），要到 `mode` 事件才分叉 ——
  纯文字回复于是也先闪一个生图占位盒再收掉。
- 改法（对齐小程序 `chat.js`）：新增 `init` / `heartbeat` / **`mode`** 三个事件的处理。
  占位盒**只认 `mode:"image"`**；`pre_text` 只管写文案（空串 = 擦掉「思考中」，擦完气泡若空了
  把三点动画放回去）；`mode:"text"` 之后迟到的 `progress` 一律不再翻出占位盒。
  没有 `mode` 的老部署仍由第一条 `progress` 兜底唤出占位盒，观感无差。

## 12. 「按住说话」——已接（方案 A：端上识别，后端零改动）

口径取自接口文档 v1.0.3 §5.1.3（Flutter 侧写得很明确）：**识别在手机本地做**，
拿到文字直接 `POST /chat`，音频不出手机。小程序同理（微信「同声传译」插件也是端上转文字），
所以**接口一个字没改，后端不参与**。

- 依赖：`speech_to_text`（iOS `SFSpeechRecognizer` / Android `SpeechRecognizer`）。
  版本写成 `>=6.6.0 <8.0.0` 而不是 `^x`：`listen()` 的参数 6.6 起才收进 `SpeechListenOptions`，
  旧的具名参数 7.0 已移除，钉这个下限两边都能编。
- 封装在 `features/ai/ai_voice_input.dart`（单例，把插件圈在一个文件里，将来要换方案只动这里）。
- 权限：Android 补 `RECORD_AUDIO` +（**关键**）`<queries>` 里的 `android.speech.RecognitionService`
  —— Android 11+ 不声明这条时 `isRecognitionAvailable()` 恒 false，表现是「按住没反应」，
  与微信登录、PayPal 外跳踩的是同一个包可见性坑；iOS 补
  `NSMicrophoneUsageDescription` + `NSSpeechRecognitionUsageDescription`（缺了请求授权直接崩）。
- 交互照小程序 `chat.js onVoice*`（仿微信）：按住开录 + 震一下 → 上滑超过 60 转「松开取消」、
  浮层变红 → 松手直接发送。**录音期间一个字都不上屏**（2026-07-27 需求 4.3），
  松手后结果直接变成一条已发送的用户消息；发不出去（协议未同意 / 图片还在传 / 星币不足 /
  建会话失败 / 被同步闸挡下）一律把文字**回填输入框**，别让人白说一遍。
- 两处 await 中间松手的边界都堵了（`_voiceHolding`）：首次按下要先弹系统授权框，
  用户很可能在那期间就松了手 —— 不挡的话麦克风会一直开到 60s 上限。

🔶 与小程序的两点差异：① **App 支持日语**（微信那个插件没有）；
② **安卓国行无 GMS 的机型没有系统识别服务**，`ensureReady()` 返回 false，按住时如实提示
「当前设备不支持语音输入」，而不是让人按了没反应。
⚠️ 真机覆盖率不能接受时，下一步才是方案 B「录音上传后端 ASR」——**那条要后端加接口**
（端上不能直连第三方 ASR：AppKey 不能进客户端）。

## 13. 设备详情：固件版本号与新版本红点

- 现状：版本号 + 红点的**画法** 2026-08-20 就写好了，缺的是**数据** ——
  本页只在进入时读 BLE（0x01），从没有人在这里拉过 `getUserProductDetail`，
  `newVersionNo` 一直是空串，`evaluateFirmwareUpdate` 于是恒判「已是最新」，**红点永远不亮**，
  要点进 OTA 页才第一次比对。小程序在 `onShow` 里就拉了。
- 改法：进页面与 `didPopNext` 都走 `_refreshDetail()`：先 BLE 读（拿设备当前版本），
  再 `fetchDeviceFirmwareInfo`（把当前版本当 `productVersionNo` 发给后端比对）。两步都静默 best-effort。
  行文案中文由「OTA升级」改为「固件升级」，与小程序一字一致。

## 14. POST 的 loading 遮罩 + AI 会话删不掉

- **遮罩**：全站扫了一遍，只有三处提交是「一次真实往返却毫无反馈」——
  修改密码 / 修改邮箱 / 补绑邮箱的确认。三处补上 `AppLoadingDialog` + `try/finally`，
  前两处的确认按钮同时改成提交中置灰（其余页面本来就有按钮转圈或遮罩）。
- **删不掉**：根因是**命中测试**，不是接口。原来一行是
  `OverflowBox(maxWidth: 卡片宽+8+80) → Row[卡片, 间距, 删除按钮]` 整条左移。画面完全正确，
  但 `RenderBox.hitTest` 会先判 `size.contains(position)`，而 OverflowBox 自己的 size 只有卡片那么宽，
  **删除按钮整块落在它的 size 之外 —— 只画不接事件**。左滑能滑开、按钮看得见、点下去毫无反应
  （长按卡片那条兜底没坏，所以不是接口问题）。改成 `Stack + Positioned`：删除按钮按
  `left = 卡片宽 + 间距 + 位移` 摆放，视觉逐像素不变，但位移多少就有多少落在 Stack 的 size 内，
  那一段就能正常命中；轨道外的部分仍由 `ClipRect` 裁掉。

## 17. AI 生成图无法保存到相册

原来只把图落到应用缓存目录，提示语还得如实写「保存到系统相册待接入插件」——
用户在相册里根本找不到。本轮补原生通道 `saveImageToGallery`：

## 22. AI 聊天：用户自己发的照片删不掉（**两端同款 bug，已同步修复**）

- 症状：AI 回复的图删了就没了；**用户自己发的照片点删除只是页面上消失，重进会话又躺在那儿**。
- 根因：历史消息映射时，用户图片消息的 `message_id` **只记在消息本身上**，`images[0].serverId`
  留空（两端都有一句「免得删整条时对同一个 id 打两次 DELETE」的注释）。
  而用户图片气泡下面那条常驻操作条走的是 `deleteBubbleImage`，它**只认 `image.serverId`** ——
  拿到空值就跳过接口、只删本地。AI 回复的图 id 记在 image 上，所以那边一直是好的,
  正是用户观察到的「一个能删一个不能」。
- 改法（App `_buildHistoryMessages` / 小程序 `buildHistoryMessages`）：**两处都记同一个 id**，
  重复改由删整条那边用 Set 去重收口（`_deleteMessage` / `deleteMessage`）。
  数据模型如实反映「这条用户图片消息就是这一个 message_id」，比靠约定记在哪一处稳。
- 影响面：只动「历史消息 → 页面模型」的映射与删除去重，删除链路本身没变。

⚠️ **另一半仍在后端**：本轮会话里**刚发出去**的消息（用户图、AI 图都一样）接口不回 `message_id`，
删除只能是本地移除，重进会话还会回来。两端源码里早有这句注释。彻底解决要后端在 `/chat`
（或 SSE 的 `done` 事件）里带回 `message_id`。端上也能绕（删除时回 `/chat/history` 按内容找回 id），
但那是每次删除多一次拉取，且同样文字发两遍会有歧义 —— **要不要绕等你定**。

### 26.4 设备详情的固件版本号：补读 0x03
上一轮补了云端字段（`newVersionNo`/`isUpdate`），但**设备当前版本**仍读不到 ——
`refreshConnectedDeviceInfo` 一直只读 `0x01`，注释里写着「固件版本 0x03 在连接/OTA 场景读取」，

最多这一次多等一个指令超时——`readDeviceInfo` 内部会吞掉 0x03 的失败、照常返回 0x01 的结果。

### 26.5 微信登录隐藏「邮箱」「修改密码」

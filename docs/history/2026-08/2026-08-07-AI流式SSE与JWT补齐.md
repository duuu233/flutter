## 零、先说最要紧的：JWT 鉴权头此前从未发送过

`boltstar_ai_api.dart` 的请求头一直只有 `Content-Type`，**没有 `Authentication: Bearer <jwtToken>`**，
而网关早在 **2026-07-29** 就强制了这个头（小程序当天就补了，见
`photo-album/docs/changes/2026-07-29-AI接口JWT鉴权头.md`，那份文档第 30 行原话就是
「Flutter…**未同步**，待移植」）。

也就是说：**App 侧的 AI 模块只要一开放入口，每个请求都会挨网关 403 `JWTTokenIsMissing`。**
之所以一直没炸出来，只是因为 `features/ai/ai_entry.dart` 的 `kAiEntryEnabled = false`
把入口整体屏蔽着，只能从调试台暗门进。

讽刺的是本文件早就移植了**识别**这个错误的 `gatewayErrorMessage()`，就是没移植**发 token** 的那半边。

本轮补上：token 取自 `ApiSession.instance.jwtToken`，每次请求现取（登录/退出后立即生效）；
未登录时不带头照发，由网关回 `JWTTokenIsMissing` 走白名单提示，不在端上另造一套错误。

> ⚠️ **开放 `kAiEntryEnabled` 之前，这一条必须在真机上单独验一次。**

## 一、`/chat` 改流式（SSE）

### 地址与协议

| | 改动前 | 改动后 |
| --- | --- | --- |
| 服务地址 | `boltstaat-agent-…`（非流式部署） | `boltstagent-web-…`（流式部署，会话/历史等接口一并切过去） |
| `/chat` 接收 | 一次性 JSON，等 15~30s | `http.Client.send` + `StreamedResponse.stream` 逐块收 SSE |
| 等待期界面 | 加载图干等到底 | `pre_text` 预描述先上屏 + 渐变占位盒里的 0→100 读数 |
| 文字 | 收齐后整段走打字机 | 边收边打（打字机追着积压走） |
| 生成超时 | 120s | 600s（客户端侧上限；真机若稳定卡在更短的点上，那是上游 FC/网关先掐的） |

**请求体、参数、鉴权方式一个字没动**，只新增一个可选的 `model_type`（`lite`/`pro`，
不传即 `pro`；页面暂无选档入口，所以正常情况下请求体与改动前逐字相同）。

### Dart 侧比小程序省下的一块

小程序要手写一整套 UTF-8 字节缓存（`onChunkReceived` 给的是 ArrayBuffer，一个汉字 3 字节
必然被切在两块之间）。Dart 的 `Utf8Decoder` 作为**流转换器**自带跨块续接，这一块直接省了。

但顺序不能反：**先 `timeout(字节流)` 再 `transform(解码)`**。反过来的话空闲超时会算在解码后的
字符流上，语义就不是「多久没收到数据」了。

### 三个必须留着的兜底

1. **`data:` 后不带空格也认** —— 文档示例代码写死 `slice(6)`，我们按 `substring(5).trim()`；
2. **字面 `\n` 分隔符还原** —— 服务端曾把事件分隔符转义成反斜杠 + n，整个响应体成了一行、
   一个真换行都没有，解析器一个事件都拿不到。只还原**当分隔符用的**那些（后面紧跟 `data:` 或已到结尾），
   JSON 正文里的 `\n` 必须原样留着，否则会把一个事件的 JSON 从中间劈开；
3. **非 200 当错误体读** —— 网关 403 的 JSON 不是 SSE，先看状态码再决定怎么读，
   比小程序那边（受 `wx.request` 语义所限只能先收再判）更直接。

解析器抽成了独立的 `AiSseParser`，收流与解析分开测（`test/boltstar_ai_sse_test.dart`，不必起真网络）。

## 二、进度补间

服务端只推 `5/15/30/45/50/80/85/90/100` 这几级里程碑，而占位盒正中间摆的是一个**数字**——
数字没法像进度条宽度那样靠动画抹平，直接贴上去就是 45→50→80 地跳。
设计稿 `assets/demo.png` 上那个 **47%** 根本不在里程碑里，本身就说明中间读数要前端补。

`_applyProgress`（记目标）→ `_pumpProgress`（每 80ms 走一步，离目标 >20 一步 3、近了一步 1）
→ `_showProgress`（上屏）。三条不变量：

- **只补到服务端给的目标值，绝不自己往前跑**；
- **只增不减**，迟到/乱序的小值连同它的 `stage` 一起丢；
- **读数真的爬到 100 的那一刻**才把占位盒换成真图（不是收到 `progress:100` 那一刻，
  否则会出现「占位盒消失时数字还停在 92%」）。流中断或漏推 100 时由收尾逻辑兜底。

⚠️ 顺带修了一个两端都有的隐患：读数到 100、占位盒收起、真图上屏之后，服务端若再补推一条
`progress`（重复/迟到的都可能），原来的写法会把占位盒**重新翻出来盖在真图上**——
`_applyProgress` 只挡了「进度倒退」，挡不住「显形」。现在 `stream.target < 100` 时才允许显形，
小程序侧同步加了同一个闸。

## 三、进度文案：服务端 `message` 优先

服务端 2026-08-07 起在 `progress` 事件上加了 `message`（`{"progress":35,"stage":"generating","message":"正在创作图片"}`）。
前端 `message` 优先、两级兜底（`stage` 映射 → 数值分档）。

**两级兜底一个都别删**：`pre_text` / `done` 本来就没有 `message`，老部署也没有，删了占位盒里会空着一行。
空串和纯空格按「没给」处理。

文案跟随**已上屏的读数**，爬到目标那一刻才用目标的 `stage`/`message` —— 否则会出现
「52% + 正在优化细节…」这种数字与文案对不上的组合。

## 四、`pre_text` 会推两条

先秒回一句占位的「星宝努力思考创作中」顶掉空等，约 3s 后 LLM 出结果再推真文案。
直接覆盖即可，不用分辨是哪一条 —— 所以代码里**没有**「只写第一次」的判断，别加。

只有贴底策略分了一下：第一条是凭空多出一块内容，强制贴底；第二条只是就地换字，
这时候再硬拽用户回底部，正在上翻看历史的人会被打断。

## 五、一键生图点下去要立刻上屏

`_sendChat` 原本是「先 `await _createSession()`（真机约 1s）→ 再把用户气泡上屏」。
空态下点风格按钮，界面得干等一整趟网络往返才有反应，像是没点着。

改成 **气泡先上屏、再建会话**；建会话失败就把刚上屏的气泡和会话标题一起撤回去。

⚠️ 顺序反转带出一个连带坑，已一并修掉：`_doCreateSession` 原本无条件写
`_sessionTitle = session.title.isNotEmpty ? … : 新对话`。新建会话后端一律回占位的「新对话」，
而这时页面上标题**可能已经**被 `_sendChat` 同步成首条用户消息了，照写就会盖回去。
现在只有后端给了真标题、或本地还是占位/空时才覆盖。

`_onSendTap`（输入框发送）**保持原样**多走一趟建会话：它有草稿要清，
而 `_sendChat` 的回滚只撤得掉气泡、撤不回已经清掉的草稿。

## 六、气泡内排版

顺序：**预描述 → 占位盒 → 真图 → 正文**。

- 正文在**图片下方**：SSE 里 `text` 事件本来就排在 `image` 之后，先出图、文字再往下续；
- 占位盒与真图必须**都在正文之前** —— 它俩是同一个位置的两个状态，跨到正文两边去的话，
  100% 换图那一下图会整块跳过正文；
- 占位盒的圆角与宽高比必须与真图那个盒子**逐一对齐**（`_AiBubbleImage` 是
  `ClipRRect(10)` + `AspectRatio(100 / pad)`），改一处就得同时改另一处；
- 进度文案压在百分比正下方、盒子**内部**（半透明白字），盒外不留字。

## 七、打字机放慢

流式打字机每帧字数 = `max(1, ceil(积压 / _kStreamTypeTicks))`。`_kStreamTypeTicks` 取 **180**（≈2.9s），
不是小程序最初那个 60（≈1s）。

原因：服务端的 `text` 事件常常连着涌进来（尤其响应体一次性到达、靠字面 `\n` 兜底解析的那条路，
所有事件在同一帧解析完），积压瞬间就是全文 —— 压在 1 秒内打完，100 字就是每帧 2 字、0.8 秒冲完，
肉眼基本看不出在打字。小程序侧同日也从 60 改到了 180，两端一致。

## 八、删掉的东西

`_renderReply` / `_startTyping`（一次性拿到全文再渲染的老路）已删：主链路是流式，
服务端只在汇总结果里给全文的情况由 `_finishStream` 兜底补进同一个打字机。
`BoltStarAiApi.chat()`（非流式）仍在，指向旧部署，只作手动回退用，页面没有接它的渲染路径。

## Known Issues

- **未编译、未真机**：本机无 Flutter SDK，`flutter analyze` / `flutter test` 都没跑过。
- **`kAiEntryEnabled` 仍为 `false`**：AI 入口依旧整体屏蔽，只能走调试台暗门（口令 `8866`）验收。

- **降级链路**：小程序有 `supportsStream()` 在老基础库上回退非流式；App 侧 `http` 一定能收流，
  所以没接自动降级，`chat()` 只是留着手动回退。

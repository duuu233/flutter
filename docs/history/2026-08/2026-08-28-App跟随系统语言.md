## 一、需求与此前的行为

需求：**按手机系统默认语言显示 App 语种，不在四语种（简中/繁中/英文/日文）范围内的默认英文。**

此前 App 的初始语种是**写死的简体中文**（`PhotoFrameState.seeded()` 里 `_language = AppLanguage.zh`），
只有用户进过一次「设置 → 语种设置」并保存，才会有 `app_language` 落盘、下次启动读回。
也就是说一个日本用户装完打开，看到的是一屏简体中文，且请求头 `language` 也发的是 2（简中），
后端返回的 FAQ / 操作指南 / 协议正文一并是简中。

## 二、生效顺序（三层，从高到低）

| 优先级 | 来源 | 谁写的 |
| --- | --- | --- |
| 1 | `LanguagePreference`（`app_language`，SharedPreferences） | 用户在「语种设置」里保存过 |
| 2 | 手机系统默认语言 → 四语种归一 | 本轮新增 `SystemLanguage.resolve()` |
| 3 | 英文 | 系统语言不在四语种内时的兜底 |

**用户选过就永远以用户为准**：系统语言只在「从没保存过语种」时说话，
包括运行期用户去系统设置改语言（`didChangeLocales`）那一路也先查偏好再决定跟不跟。
反过来，跟随系统时**不写盘**——不落盘才叫「跟随」，落了盘就等于替用户做了一次选择。

## 三、映射规则（`lib/src/shared/l10n/system_language.dart`）

| 系统 Locale | App 语种 |
| --- | --- |
| `zh` / `zh-CN` / `zh-SG` / `zh-Hans*` | 简体中文 |
| `zh-Hant*` / `zh-TW` / `zh-HK` / `zh-MO` | 繁体中文 |
| `en*`（`en-US` / `en-GB` …） | English |
| `ja*` | 日本語 |
| 其余（`ko` / `de` / `fr` / `th` / `ru` …） | **English（兜底）** |

繁体的判据是「`Hant` 脚本**或**台/港/澳地区」两条并列：部分安卓机只报地区不报脚本
（`zh_TW` 而没有 `#Hant`），只认脚本会把台湾用户判成简中。

## 四、与小程序的有意差异（不是漏改）

小程序 `utils/language.js` 的 `normalizeLanguage` 兜底是 **`zh-Hans`**，App 这边兜底 **英文**。
两端在这一点上**有意不同**，按本次需求口径：一个韩国/德国用户开屏撞上一屏看不懂的中文，
比看到英文糟糕得多；英文是这类场景的通行兜底。归一规则本身（繁体认 Hant/TW/HK/MO、
`ja`/`en` 按前缀）两端一致。小程序侧**本轮不动**。

## 六、注意

- `platformDispatcher.locale` 取的是系统语言列表的**第一项**（= 系统默认语言），
  **不遍历**用户的备选语言列表——需求口径就是「按系统默认语言，不在四语种内就英文」。
- 请求头必须跟着一起定：`ApiSession` 的默认语言码是 2（简中），
  只改界面不改请求头的话，英文系统用户会拿到英文外壳 + 简中后端文案。
- ⚠️ 本机无 Flutter SDK，本轮新增/改动的用例一个都没跑过，合入前必须补跑
  `dart analyze` 与 `flutter test`。

## 1. 首页六大入口宫格（对端：底栏两格 + 入口收进首页）

小程序把底栏由四格收回**两格（首页 / 我的）**，原来中间两格的「AI助手」「官方图库」，
连同「我的上传」「我的设备」，一起收进首页的 3×2 宫格。App 同步：

- `home_main_view._castSection` 由「小标题 +（拍照/相册）两张卡」改为**六项宫格**，
  **小标题「选择投屏方式」按产品要求去掉**（六项里已有四项与投屏无关，这句话把入口说窄了）。
- 新增 `home_widgets._HomeEntryCard`：卡 206×220rpx（`AspectRatio(206/220)`）、圆角 14、
  半透明白 0.55 + 与设备卡同一套阴影；卡内「图标 33 + 20 间距 + 标题/副标题」整组垂直居中，
  右侧箭头徽标 25。旧的 `_CastEntryCard` 随之删除（否则 `unused_element`）。
- ⚠️ **卡宽仍然不写死**（沿用旧卡的教训）：rpx 是按屏宽等比的单位，写死逻辑像素会在窄屏溢出；
  三列由 `Expanded` 等分、卡内只按比例定高。不足三项时用空占位补齐，剩下的卡才不会被拉宽。
- 目标页一字未改：拍照/相册仍走 `_startCast`；我的上传 = `AppRoutes.figmaGallery`（与「我的」页那张卡同一目的地）；
  AI = `openAiChat`（含「接着上次那一页」的续聊口径）；官方图库 = `openOfficialGallery`；我的设备 = `AppRoutes.figmaMyDevices`。

## 4. 低电量提醒（10%~4% / ≤3%）

新增 `lib/src/shared/widgets/low_battery_tip.dart`：

- `lowBatteryBandFor(int?)` —— **纯逻辑**分档（`none/low/critical`），单独抽出来是为了不依赖
  BuildContext 就能测（`test/low_battery_band_test.dart`，与小程序 `tests/low-battery-tip.test.js` 同一组用例）；
- `showLowBatteryTipIfNeeded(context, state, deviceId)` —— 取电量 → 落档 → 弹 `showAppNoticeDialog`。
  **不阻断**原动作（弹窗只是告知），await 只是为了不和紧随其后的 loading 蒙层抢屏。
- 电量取值走新增的 `state.batteryForActionTip(deviceId)`，它复用既有的 `_refreshDeviceBattery` +
  `DeviceBatteryCache`（15 秒内复用最近一次 0x04），所以「点一下弹一次」不会变成「点一下多发一条 BLE 指令」；
  从未读到过电量时返回 null → **不弹**（没有判据就不报警）。

⚠️ 分界线：需求原文是「10%~4%」与「3% 以下」，字面上 3% 落在两档中间的缝里；第一档明确到 4% 为止，
所以 **3% 归第二档**（弹窗文案本身也写着「低于3%」），与小程序 `CRITICAL_BATTERY_MAX` 一致。

**挂在哪**（小程序是挂在 `ensureConnectedForAction` 这个唯一入口上，App 侧没有同名收口，故挂在两处 UI 的连接口）：

| 位置 | 覆盖的操作 |
| --- | --- |
| `home_page._ensureConnected` | 首页「连接蓝牙」、拍照/相册投屏（未连接时的自动扫连之后） |
| `home_page._startCast` 的**已连接分支** | 已连接时点投屏——这一支不走连接流程，得单独补（对齐小程序 `ensureCanProject`） |
| `devices_page._ensureConnected` | 设备列表的连接 / 投屏 / 进详情前的连接 |

⚠️ **自动连接不弹**这条口径靠「只挂在 UI 的主动操作入口、不挂在 `state.connectDevice`」保证——
后者也被投屏流程内部的续连调用，挂上去会在图传中途弹窗打断流程。
⚠️ 仍**未覆盖**：我的相册再投/删除、轮播设置保存、一键清空、OTA 升级这几处的自动重连
（App 侧它们各自调 `state` 的方法、没有统一的 UI 连接口）。要补齐得在各自页面的动作入口再调一次，
留作下一轮——小程序那边这些是靠单一收口顺带覆盖的。

## 6. **不适用**的两项（核对结论）

- **主按钮改橙色渐变**：小程序当天把「渐变 → 底图」又反转回「全站渐变」。
  App 侧主按钮本来就是渐变（`_GradientButton` 等），`assets/images/primary-btn-bg.png` 在 lib 里
  **一处引用都没有**——最终状态两端已经一致，无需改代码，顺手把那张 122 KB 的孤儿图删了。
- **图片详情大图与白卡断层**：小程序那条 bug 的根因是「大图 `position:absolute` 从屏幕顶端起算，
  而白卡在 `.fold-scroll` 里、从导航栏下沿起算」，两者差一个导航高度。
  App 侧 `official_gallery_detail_page` 是 `Stack` + `Positioned(top:0)` + 同一个 `Stack` 里的
  `SingleChildScrollView`，**两者同起点**，`spacerHeight = heroHeight - 3% 屏高` 本来就正确 —— **无此问题**。
- **支付方式文案「微信虚拟支付」→「微信支付」**：App 侧没有购买页（购买走 Apple IAP / Android 内购、尚未接入），
  仓库里出现这个词的只有两处注释，且都是在如实描述小程序的通道，**不改**。

1. **引用的图必须存在** —— Flutter 引用不存在的图**不会编译报错**，只会运行时抛异常或落 errorBuilder，

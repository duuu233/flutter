## 一、为什么还欠着这一轮

小程序侧「主动点击才弹、自动连接不弹」是**结构上**成立的：所有主动操作都收口在
`active-device.ensureConnectedForAction`（连上后弹），自动重连走 `ensureDeviceConnected`（不弹），
一处改动全站生效。

App 侧**没有同名收口**——每个页面各自调 `state.connectDevice`，提醒只能在各自的动作入口手动补一次。
08-21 那轮先补了三处（首页 `_ensureConnected`、首页 `_startCast` 的已连接分支、设备列表
`_ensureConnected`），剩下的按当时的记录「留作下一轮」。本轮把那张表补完。

## 三、几处需要解释的做法

**「一次点击只弹一次」——OTA 那条链路。**
详情页「立刻更新」（`startOtaFlow`）弹过之后会 push `OtaUpgradePage(autoStart: true)`，
那一跳的设备本来就连着，若在 `_doRunUpgrade` 里无脑弹就成了一次点击弹两遍。
新增 `_lowBatteryTipDoneByEntry`（初值 = `widget.autoStart`）**一次性消费**：
只跳过自动开始的第一轮，此后本页的手动「连接并升级 / 重新升级」照常各弹各的。
用一次性标记而不是直接判 `widget.autoStart`，是因为后者是页面级常量——升级失败后手动重试时
它仍是 `true`，会把该弹的那一次也吞掉。

**投屏记录「再次投屏」把一段 loading 拆成了两段。**
原来「连接 + 下载」共用一条 `castConnectingDevice` 蒙层。提醒要单独出现在干净的屏上，
所以连上后先 `AppLoadingDialog.hide` → 弹提醒 → 再 `show` 继续下载。
`hide` 只精确移除自己那条路由、重复调用静默返回（见 `app_widgets.dart`），
所以外层 `finally` 里那次 `hide` 依然安全。「我的相册」的再投链路本来就是分两段写的，两处现在同形。

**两处相对小程序有意的收窄：删除、轮播保存。**
小程序那边是「先连上再弹」（连接前置在页面里）；App 侧这两条链路的自动扫连分别发生在
`state.deleteDevicePhotoSlots` 与 `state.setDeviceCarousel` **内部**——连接前置刻意留在 state 层
（2026-08-20 那份记录里写明的决定），页面拿不到「刚连上」这个时刻。
所以这两处只在**本来就连着**时提醒；未连接时端上此刻读不到电量 → 不弹，
与「电量未知一律不弹（没有判据就不报警）」是同一条口径。
轮播设置页的入口本来就要求已连接才放进来，实际影响只在删除那条上。

**投屏结果页「继续投屏」也只在已连接时弹。**
这一支自己不建连接——连接发生在下一页（预览页预热 / 投屏页续连），那属于**自动连接**、按口径不弹。
官方图库详情页与 AI 对话页则相反：它们在 App 侧**自己就在页面里连**（小程序是到预览页才连），
所以这两处比小程序覆盖得更全，已连接与刚连上都会提醒。

**红线没动：自动连接一律不弹。**
`state.connectDevice` 本身、预览页预热、`projection_service` 图传中的续连、`ble_controller`
全都没有也不许有提醒——挂上去会在图传中途弹窗打断流程。

## 五、测试

新增 `test/low_battery_entries_test.dart`——**文件粒度**的静态核对（读源码、剥注释）：

1. 上表每个入口文件都必须出现 `showLowBatteryTipIfNeeded(`；少一个就红；
2. 反过来，**没登记在册的新调用点**同样红，逼着下一个人先想清楚「这是用户按下按钮，
   还是流程内部的自动重连」；
3. `state.dart` / `cast_preview_page.dart` / `projection_service.dart` / `ble_controller.dart`
   四处自动连接链路**一律不许**出现它——这是「自动连接不弹」在 App 侧唯一的红线。

之所以只做文件粒度：调用时机与参数属于真机回归，静态扫描证不了。
分档逻辑本身仍由 `test/low_battery_band_test.dart` 钉住（与小程序 `tests/low-battery-tip.test.js` 同一组用例）。

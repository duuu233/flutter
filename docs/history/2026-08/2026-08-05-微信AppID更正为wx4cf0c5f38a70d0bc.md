## 原因

之前配置的 `wx5bc2000b3207f370` 不是本 App 对应的移动应用，AppID 本身就是错的。
微信按「AppID + 包名/Bundle ID + 签名」识别移动应用，AppID 错则授权链路的所有下游排查都无意义。

## Android / iOS 与 debug / release 的一致性

AppID 在本项目只有两个落点，改完即三端一致：

| 落点 | 作用范围 |
| --- | --- |
| `WeChatAuthorizationConfig.fromEnvironment()` 的 `defaultValue` | Android + iOS，全部构建类型 |
| `ios/Runner/Info.plist` → `CFBundleURLSchemes` | 仅 iOS 回跳 |

Android 原生侧不写 AppID：fluwx 的 `registerApi()` 由 Dart 传入，`WXEntryActivity` 由 fluwx
的 Manifest 合并生成，因此 Android debug/profile/release 与 iOS 共用同一个 Dart 默认值。
只要不传 `--dart-define=WECHAT_APP_ID` 覆盖成别的值，debug 包与 release 包的 AppID 必然相同；
Android 三种构建的签名此前已统一为 `boltstar-release.jks`（MD5
`93d4d761713340c5645dc4faa378ddd1`），所以 debug 包同样可用于微信授权验收。

## 影响

- 源码中已无 `wx5bc2000b3207f370`；文档里仅在「旧值已作废」的对照说明和历史记录中保留该串。
  `build/` 下的旧产物仍内嵌旧 AppID，需重打。
- 用旧 AppID 打出的所有 Android/iOS 安装包作废，必须用新 AppID 重新构建后再验收。
- 后端的 `WECHAT_MOBILE_APP_ID` / AppSecret 必须换成新移动应用的那一对，否则
  `/sns/oauth2/access_token` 会因 appid 与 secret 不匹配失败。
- 微信开放平台需在 `wx4cf0c5f38a70d0bc` 这个移动应用下重新核对：包名 `com.boltfox.boltstar`、
  应用签名 `93d4d761713340c5645dc4faa378ddd1`、iOS Bundle ID 与 Universal Link。

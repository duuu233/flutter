## 1. Flutter 多设备问题

### 现象

两台设备尺寸相同，但完整设备 ID 和用户名称不同。用户点击 A 时，App 可能连接并认领 B。

### 根因

1. 广播厂商数据只包含 4 字节短 `Device_ID`，同批次设备可能相同。
2. `matchScannedDevice` 用“短 ID + 屏幕尺寸”命中第一个扫描候选。
3. `connect` 建连后虽读取 `0x01` 的 6 字节完整 ID，但 `connectBoundDevice` 没有把它与
   用户点击设备的后端完整 ID 做最终核对。
4. `sessionMatchesSerial` 只要会话任意序列号与目标命中，就允许复用；共享短 ID 会盖过完整 ID 不同。
5. 设备名称是可编辑展示字段，广播名通常又只是产品型号，因此名称不能作为物理身份。

### 修复

- `serial_match.dart`
  - 新增 `serialSetsMatch`：双方存在同长度 ID 时，以最长共同长度精确裁决。
  - 新增 `verifiedDeviceSerialMatch`：后端为 6 字节完整 ID 时只接受完整 ID 精确相等。
  - 新增 `sessionSerialsMatch`：完整后端 ID 不得只凭会话短 ID 复用。
- `ble_controller.dart`
  - 活动会话复用前补读/核对 `0x01` 完整 ID。
  - 扫描广播只作为候选筛选。
  - 建连后执行完整 ID 验身；不一致立即断开，排除该 BLE `remoteId` 后继续扫描。
  - 最多核验 4 个候选，避免异常广播环境无限循环。
  - 日志输出 expected/actual/broadcast/name，便于真机追踪。
- `serial_match_test.dart`
  - 覆盖“两台共享短 ID、完整 ID 不同”、完整 ID 不得降级短码复用、老设备短 ID 兼容。

## 2. 电量策略复核

小程序最终改为缓存优先：最近有效值立即展示，15 秒内复用，超窗后台刷新，失败保留旧值。

Flutter 当前本来就是“旧值持续显示、后台刷新”的体验：

- `DeviceItem.batteryLevel` 保留最近一次 BLE 有效值；
- `refreshDevices` 整体替换列表时，`_carryOverBleFields` 会搬运电量；
- 首页/设备列表/详情触发 `refreshConnectedDeviceInfo` 时不会先清空 UI；
- `0x01` 成功后 `_applyConnectedInfo` 原位替换，失败保持旧值。

因此 Flutter 不存在小程序本轮的 `-- → 真值` 闪烁，不需要为了形式对齐而先清空或改成 nullable。
App 的 25 秒 `0x04` 是连接保活心跳，结果不作为页面值；页面缓存仍由最近一次成功的核心信息读取更新。

## 3. 验收

1. 准备 A/B 两台同尺寸设备，完整 ID、名称不同，广播短 ID 相同。
2. 点击 A：即使先扫描到 B，也应在 B 建连后的完整 ID 校验中断开，继续找到 A。
3. 点击 B：行为同上，最终 `BleController.info.deviceId` 必须等于 B 的完整 ID。
4. A 已连接后点击 B：先断 A，再按完整 ID 验身连接 B；列表最多一台显示已连接。
5. 快速切换首页、设备列表、详情：Flutter 电量保持旧值直到刷新完成，不出现人为清空的 `--`。

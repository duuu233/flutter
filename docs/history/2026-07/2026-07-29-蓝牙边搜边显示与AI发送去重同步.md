## Problem

### 1. 7 台同时在场经常搜不全

两个客观条件叠在一起：设备广播 ID **每 3s 才发一次**；多台同时在场还要抢同一条广播信道。
12s 窗口下每台设备只有几次现身机会，7 台同时测经常少 1~2 台。

但**单方面拉长窗口不可行**：改前 `_startScan` 是「`_Stage.scanning` 整段挂着雷达页 → `await _ble.scan()`
返回后才一次性 `_Stage.found`」，`BleController.scan` 的 `onUpdate` 增量回调压根没接。
用户必须干等满整个窗口才看得到**任何**一台，窗口越长干等越久——这也是「窗口」和「交互」必须一起改的原因。

### 2. AI 加载中气泡占满屏宽

AI 气泡按需求铺满屏宽（`_buildBubbleRow` 里 `Expanded` + 气泡 `width: double.infinity`）。
但「等待回复」的占位气泡里只有三个跳动的点，铺满就成了一个占满整行的空白大框，看着像出错或空回复。

### 3. AI 首次发送能连点重复发出去

`_sending` 要等 `_sendChat` 内真正发出请求那一刻（追加 loading 气泡时）才置起，而在它之前还隔着
「AI 服务协议确认 + 建会话」最多两次网络往返。**首次进入 AI 在空态发第一条消息**时这段空窗最长
（必须先 `POST /session/new`），期间发送按钮仍是亮的、`_onSendTap` 开头的守卫里 `_sending` 仍是 false，
用户连点就能把同一条消息发出去好几遍。`_createSession` 的在途去重只去重了「建会话」，挡不住「发送」。

### 4. 设备详情页看不到物理分辨率

用户要求在「设备ID」后面看到屏幕物理分辨率（如 `680*960`）。

## Solution

### 1. 边搜边显示 + 窗口 20s（`bind_device_flow.dart` / `bind_device_found.dart`）

- `_scanTimeout = 20s`（与小程序 `bind.js SCAN_TIMEOUT_MS` 同值）：按 3s 广播间隔算，每台约 6~7 次现身机会。
- 接上 `_ble.scan(onUpdate: ...)` → `_applyScanResult`：搜到一台就渲染一台，搜到第一台即 `_Stage.found`。
- **新增 `_scanning` 与 `_stage` 分开存**：stage 已经是 `found`（列表在显示）而扫描仍在继续，
  两者同时为真才是「边搜边显示」。`found` 页据此让雷达继续转（复用搜索页那张 `search-devices.gif`，
  两页视觉连续）、标题改「正在搜索…已找到 N 台」、隐藏「重新搜索」（列表正在自己长，重搜只会清光重来）、
  多出一个「停止搜索」文字链。
- **`_scanOrder` 首见顺序钉死展示序**：`BleController.scan` 回吐的是**按 RSSI 降序**的列表，
  边搜边渲染时信号一抖动整列表就重排，行与行来回跳，用户指头底下那台可能在按下的瞬间换成了别台（误绑）。
  首见序号一旦分配不再变，列表只增不重排。连带 `bind_device_found.dart` 的默认选中语义从
  「信号最强那台」变成「最先搜到那台」（都是 `entries.first`，注释同步改）。
- **`_scanSeq` 轮次号**：停扫/重搜自增，在途扫描的增量与最终结果按 seq 对不上直接丢弃。
  在途 `scan` 仍会在自己 timeout 到点后 return，但那时 seq 已对不上——不丢就会把已经停下的那一刻的
  列表又盖回去，甚至把用户已选中的那台挤动。
- **`_stopScanForBind()`**：立刻停扫但**保留已搜到的列表**，两个入口：① 点「停止搜索」；
  ② 搜索还没结束就点「立即绑定」。必须 `await`：扫描与连接抢同一路射频，边扫边连本就是「连不上」的
  主因之一。`_bind` 因此先 `await _stopScanForBind()` 再 connect。
- **`_binding` 改为在任何 await 之前同步置起**：新增的等停扫 await 会给连点留空窗（与 AI 那处同款病灶）。
  `index < 0` 早退补 `_binding = false`，避免按钮被永久锁死。
- **`_cancelScan()`**：搜索页「取消」从 `Navigator.maybePop` 改为先停扫再退——不停扫就走，
  20s 窗口会在后台继续占着射频，妨碍下一次进来重扫（这是 20s 窗口放大出来的问题，12s 时也在，只是短）。

新增底层能力：`FrameBleClient.stopScan()`（`FlutterBluePlus.stopScan()`，异常吞掉，停扫是幂等意图）
+ `BleController.stopScan()`（没在扫时空操作；在途 `scan` 会因此提前 return，
`scanning` 由它自己的 finally 归位，这里不抢着改状态）。

### 2. 加载气泡按内容收缩（`ai_chat_page.dart`）

`_buildBubbleRow` 对 `message.loading` 的 AI 行改用 `Flexible`（其余仍 `Expanded`），
`_buildAiBubble` 里 `width: message.loading ? null : double.infinity`。
内容一到（content/images 上屏、`loading` 转 false）就回到铺满的正常 AI 气泡。

> 与小程序的实现差异：小程序是 CSS 类 `.bubble--ai.bubble--loading { width:auto; max-width:520rpx }`，
> Flutter 是布局约束（`Flexible` + `width:null`），无需显式 max-width——`Flexible` 已经封顶在行宽。

### 3. 发送入口加同步闸 `_submitting`（`ai_chat_page.dart`）

`_guardedSend(task)`：在**任何 await 之前**同步 `setState(() => _submitting = true)`，finally 归位，
返回 false = 被闸挡下。发送按钮的亮/灰与文字色都加上 `!_submitting`。

覆盖两条发送路径：`_onSendTap`（发送按钮）、`_onStyleTap`（一键生图，也要先建会话）。
`_startNewSession` 也一起挡 `_submitting`——否则空窗期点＋会「界面退回空态 + 消息仍发进新建会话」
两个矛盾结果。`_onSendTap` 内 `await _sendChat(...)`，让 `_submitting` 一直持有到请求真正发出、
`_sending` 接棒，中间不留空窗。

> 小程序还多一条 `sendVoiceText`（语音松手，被闸挡下时把文字回填输入框）和 `beginVoice`：
> **App 端语音输入本就未实现**，无对应落点。

### 4. 详情页分辨率行（`device_details_page.dart` / `state.dart` / `app_l10n.dart`）

- `state.dart`：`DeviceItem` 新增 `screenWidth` / `screenHeight`，在设备记录映射处原样存后端下发的 `width`/`height`。
  **不能直接用 `screenType` 反查 `FrameProtocol.screenTypes`**：`_screenTypeFromSize` 在后端没下发尺寸时
  会**回落 5.89 寸**，反查就会显示一个臆造的 `680*960`。原始宽高为 0 就老实显示 `--`。
- `_resolutionText(device, connected)`：已连接用 0x01 读到的真机宽高（`BleController.instance.info`，
  7.3 寸占位型号权威表里是 0×0，继续往下兜）→ 后端记录宽高 → `--`。
- 与设备ID/内存不同，分辨率是**产品静态属性**而非实时数据，所以**不跟随连接状态置 `--`**：
  未连接时后端记录里的宽高一样准，硬要置 `--` 只会让常态未连接的设备永远看不到分辨率。
- `app_l10n.dart` 新增 `bindScanningFound(count)` / `bindStopScan` / `devResolution` 三条（四语种口径同现有条目）。

## 与小程序的差异

| 点 | 小程序 | Flutter |
| --- | --- | --- |
| 停扫底层 | `bluetooth.stopDiscovery()` + `bluetooth.whenScanStopped()`（已存在，多订阅者共用一路扫描） | 新增 `FrameBleClient.stopScan()` / `BleController.stopScan()`；`scan()` 内部等的是「`isScanning` 转 false 或 `until` 命中」，停扫即当场收网并把已搜到的正常 return，不需要单独的 `whenScanStopped` |
| 分辨率取值 | `SCREEN_TYPES[screenType]` → 后端 `width/height` → `--`（后端记录不带 `screenType`，只有连上后 0x01 才有，不会臆造） | 连上用 `info.width/height` → `DeviceItem.screenWidth/Height` → `--`（**不能**反查 `screenType`，见上） |
| 加载气泡收缩 | CSS `width:auto; max-width:520rpx` | 布局约束 `Flexible` + `width:null` |
| 语音发送去重 | `sendVoiceText`/`beginVoice` 一并加闸 | 语音输入未实现，无落点 |
| 搜索中的雷达 | 同一张 gif（`scanning` 门控 wx:if） | `found` 页 `scanning` 时用同款 gif，非搜索态才回 `FigmaBluetoothRadar(found)` |

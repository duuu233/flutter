## Problem

App 的微信登录一直发到 `/Client/User/setWechatAppLogin`——那是**小程序**的「授权手机号一键登录」，
入参 DTO `WechatAlipayGetPhoneNumberApiInput` 还要 `wxEncrypData` / `wxIvData`（小程序手机号解密数据），
移动应用 OAuth 根本拿不到。所以微信登录从未真正走通过。

第二个隐患在网络层：`ApiClient` 的连接层失败（`ClientException` / `IOException`）**一律重试 2 次**，
只有超时可以用 `retryOnTimeout` 关掉。微信 code 是一次性凭证，「请求已发出、响应途中断」时
服务端可能已经拿它换过 access_token，重发同一个 code 必被微信判 40163，
用户看到的却只是「微信登录失败」——查起来会一路查到 SDK 和开放平台配置上去。

## Solution

接口按 swagger 确认为 `POST /Client/User/setWechatAuthorizLogin`
（摘要「微信授权登录」，入参 `WechatAuthorizLoginApiIn`，响应 `BaseOutput«UserInfoDetailApiOut»`，
与邮箱登录同一响应模型）。DTO 里的 `device` / `language` / `terminal` 均注明「通过 headers 传递」，
即公共参数，body 只发 `code`。

一次性 code 的三道闸：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| SDK | `FluwxWeChatAuthorizationClient._pendingAuthorization`（原有） | 同一次授权只在途一个请求 |
| 业务 | `PhotoFrameState._consumedWeChatCodes`（新增） | 提交过的 code 不再提交第二次 |
| 网络 | `ApiClient.postJson(retryOnConnectionError: false)`（新增开关） | 超时/连接中断都不自动重试 |

`retryOnConnectionError` 默认 true，**只有微信登录这一个接口传 false**：其余接口连接没建立就不可能
有副作用，重试是净收益。测试里放了对照组（`userLogin` 连接中断仍发 3 次）守着这条边界。

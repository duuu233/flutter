## Problem

设备名允许重复，两台设备可以同名。小程序侧图库下拉整条链路以设备名为键，同名设备会被去重成一项、照片混在一起。

Flutter 侧问题略有不同但同源：下拉直接吃 `state.devices` 渲染，`_photos` 已经按 `photo.deviceId == _deviceFilter` 过滤（筛选本身没串台），但

- 下拉里两台同名设备显示成两个**一模一样的名字**，用户无法分辨点哪个；
- 下拉项只来自 `state.devices`，**已解绑设备的老照片**没有对应筛选项，永远筛不出来；
- 没有 `deviceId` 的老照片（后端未回 `userProductId`）同样筛不出来。

## Solution

新增 `_DeviceFilterOption { id, label, rawLabel, serialTail }`，对齐小程序 `list.js` 的 `{ label, rawLabel, value }`：

- **`_filterOptions`**：以 `state.devices` 全量绑定设备为主（含刚绑定还没照片的），再并入「照片里带的设备ID、但设备列表里没有的」兜底；全程按设备ID去重。
- **`_disambiguateLabels`**：重名时 label 补序列号尾 4 位（如 `客厅相框(D428)`），取不到序列号则按出现次序补 `(2)`/`(3)`。`rawLabel` 保留原始设备名。
- **`_serialTail`**：`DeviceItem.serialNumber`（`AA:BB:…:FF`）去分隔符后取尾 4 位。
- **`_photos`**：`photo.deviceId == filter`；照片无 `deviceId` 时按 `rawLabel` 兜底匹配（同名设备下这类照片会两台都出现——无 ID 无从区分，接受降级）。
- **`_filterLabel` / `_ensureDeviceFilter`**：都改走 `_filterOptions`，选中态与回调一律用 `option.id`；设备列表为空但有照片兜底项时选首个兜底项。
- **`_DeviceFilterChip` / `_FilterMenu`**：入参 `devices: List<DeviceItem>` 改为 `options: List<_DeviceFilterOption>`。

## 与小程序的差异

| 点 | 小程序 | Flutter |
| --- | --- | --- |
| 筛选值 | `device.userProductId \|\| device.id` | `DeviceItem.id` |
| 序列号来源 | `deviceNo \|\| productDeviceId` | `DeviceItem.serialNumber` |
| 展示名字段 | data 新增 `currentFilterLabel` | 已有 `_filterLabel` getter，改走 options |
| 槽位推算的设备归属 | 本次一并修正（原「ID 或 名字」匹配会让同名设备照片一起排队推算 → 刷错图） | `state.dart` `_resolveDeviceImageIndex` 本就只按 `deviceId` 匹配，**无需改动** |

## Problem

设备名允许重复，两台设备可以同名。小程序侧图库下拉整条链路以设备名为键，同名设备会被去重成一项、照片混在一起。

Flutter 侧问题略有不同但同源：下拉直接吃 `state.devices` 渲染，`_photos` 已经按 `photo.deviceId == _deviceFilter` 过滤（筛选本身没串台），但

- 下拉里两台同名设备显示成两个**一模一样的名字**，用户无法分辨点哪个；
- ~~下拉项只来自 `state.devices`，**已解绑设备的老照片**没有对应筛选项，永远筛不出来；~~
- ~~没有 `deviceId` 的老照片（后端未回 `userProductId`）同样筛不出来。~~

⚠️ 2026-07-30 起后两条按用户要求**不再解决**：下拉项只来自设备接口，这两类照片筛不出来是预期行为（见操作日志）。

## Solution

新增 `_DeviceFilterOption { id, label, serialTail }`，对齐小程序 `list.js` 的 `{ label, value }`：

- **`_filterOptions`**：**完全**以 `state.devices` 全量绑定设备为准，返回几台就几项（含刚绑定还没照片的），按设备ID去重。~~再并入照片里的历史设备兜底~~（2026-07-30 已删）。
- **`_disambiguateLabels`**：重名时 label 补序列号尾 4 位（如 `客厅相框(D428)`），取不到序列号则按出现次序补 `(2)`/`(3)`。设备名只用于展示，不参与任何匹配/合并。
- **`_serialTail`**：`DeviceItem.serialNumber`（`AA:BB:…:FF`）去分隔符后取尾 4 位。
- **`_photos`**：只按 `photo.deviceId == filter` 匹配。~~照片无 `deviceId` 时按 `rawLabel` 兜底匹配~~ ⚠️ 2026-07-30 已删设备名兜底，`rawLabel` 字段一并删除，勿再加回。
- **`_filterLabel` / `_ensureDeviceFilter`**：都改走 `_filterOptions`，选中态与回调一律用 `option.id`；设备列表为空即无筛选项，`_deviceFilter` 置 `null`。
- **`_DeviceFilterChip` / `_FilterMenu`**：入参 `devices: List<DeviceItem>` 改为 `options: List<_DeviceFilterOption>`。

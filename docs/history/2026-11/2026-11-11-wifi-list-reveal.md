# 选择 WiFi 页搜一个显示一个、列表出来后头部不再转圈（main-wifi）

> 类型：Historical Implementation Record
> 日期：2026-11-11；环境：远程 SSH 服务器；分支：main-wifi；修改前：1b84812
> 依据：产品反馈 ① WiFi 列表出来了头部还在显示搜索中；② 搜索 WiFi 很慢，是否设备原因；③ 希望像搜索蓝牙设备一样搜一个显示一个。与小程序 main-wifi 同日改动一致。

## 原因

- ① 列表每收到一批就显示，但 `_scanning` 要等 `scanWifi` 结束——设备不发「列表结束」标记，`Blufi.wifiListQuiet` 在最后一批后再静默 5 秒才判结束，所以列表出来后头部至少还转 5 秒。
- ② 等待 = 设备扫描（双频 2.4G + 5G 逐信道扫完才回结果，设备侧耗时，前端无法加快）+ 蓝牙回传 + 5 秒静默。第三段的「慢感」本次已从界面去掉；前两段需看真机日志（本次加了耗时日志）。
- ③ 设备按批回，一批几十条整批一次性出现。

## 改动

- `wifi_list_page.dart`：
  - 转圈（正在连接设备 / 正在搜索网络）只在 `_list` 为空时显示；列表出来后头部即「重新搜索」、底部「手动输入WiFi名称」同时出现。后台照旧收后续批次，静默 5 秒判结束不变（只用于空列表 / 未返回提示）。
  - 每批交给 `_reveal`：没显示过的按信号从强到弱每 100ms 亮一条（第一条立即），已显示的跟着刷新信号与位置；扫描结束时没亮完的一次补齐；`dispose` 取消定时器。
  - 新行 `_WifiRowFadeIn`（`TweenAnimationBuilder` 淡入下滑 260ms），按 ssid 作 key，刷新 / 排序不重播。
  - `_rescan`：列表出来后不等收尾即可重搜；`_scanSeq` 让旧一轮之后回来的批次 / 结果作废，重搜先清空列表（BluFi 流是 broadcast，新旧两轮监听可并存）。
  - `debugPrint('[WiFi列表] ...')` 打出发出扫描到每批回来的毫秒数、总批数与含收尾等待的总耗时。
- 新增 `test/wifi_list_reveal_test.dart`（源码静态核对）。

## 验证

- 本机无 Flutter / Dart，未 analyze / test / 真机；新测试的匹配用 python 对实际源码核对通过，括号配平、git diff --check 通过。
- 真正「设备扫到一个就回一个」需固件按信道分段扫描并逐段上报；前端已能直接接住。

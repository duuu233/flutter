# WiFi 固件升级进度条：19 / 39 / 59 / 79 必须等到下一档数值（main）

> 类型：Historical Implementation Record
> 日期：2026-11-13；环境：远程 SSH 服务器；分支：main；修改前：5bcd311
> 依据：产品口径——0~20 由前端自己匀速走到 19，之后在 19 / 39 / 59 / 79 停住等 `progress` 上报（19 等 20、39 等 40、59 等 60、79 等 80），收到后继续前进；固件不上报（null）走到 98 停住。同小程序同日改动。

## 问题

2026-11-12 的 `otaProgressCap` 里有两条按状态直接放开到 98 的分支，会越过等待点：

- 进入 `FLASHING` 一律放到 98：例如收到 60 后状态变成写入，进度从 79 不等 80 直接走到 98；
- 进入 `DOWNLOADING` 但还没收到数值就放到 98：状态先于 20 到达时，19 不等 20 直接走到 98。

## 改动（`wifi_ota.dart`）

- 状态只决定步骤，不再放开分档；上限只看收到过的最大进度：没收到 19，收到 20 / 40 / 60 / 80 走到 39 / 59 / 79 / 98。
- 「固件不上报」改为：一个数值都没收到就已进入 `FLASHING` → 98；下载阶段为 null 仍停 19（可能只是 20 还没到）。
- `VERIFYING` / `SUCCESS` 100、失败停住、只认最大进度、本地记录续走均不变；页面 `wifi_ota_page.dart` 未改。

## 验证

- `test/wifi_ota_test.dart` 上限用例改为新口径：`DOWNLOADING` + null 为 19，`FLASHING` + 40 / 60 / 80 为 59 / 79 / 98，`FLASHING` + null 为 98。
- 本机无 Flutter / Dart，analyze / test / 编译 / 真机都没跑；OTA 进度未联调。

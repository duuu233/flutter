# 星币数值被截成「75… Stars」——改为整行等比缩放

> 文档类型：Historical Change Record
> 日期：2026-09-11
> 环境：SSH（本机无 Flutter SDK）
> 分支与起始版本：main / `858ad7d`
> 范围：`lib/src/features/star/presentation/star_coin_page.dart`、`test/star_package_amount_no_ellipsis_test.dart`
> 相关：同一张卡的收窄过程见 `docs/history/2026-09/2026-09-08-star-package-card-badge-width.md`

## 现象

Stars 页「Buy stars」套餐卡上的星币数显示成 `75… Stars`，数值被省略号截断。
产品口径：**字体可以小一点，但数值要完整展示**；当前档位上限 30000。追加一条：
后面的单位（`Stars`）也可以跟着缩小。

## 根因

卡片在 2026-09-08 当日三次收窄（150 → 138 → 124 → **104**，对齐小程序 208rpx），
而这一行的排版没跟着改：

```dart
Row(children: [
  Flexible(child: Text('${package.tokens}', overflow: TextOverflow.ellipsis,
      style: TextStyle(fontSize: 20, fontWeight: w700))),
  SizedBox(width: 4),
  Text(l10n.aiTokenUnit, style: TextStyle(fontSize: 13)),
])
```

内容宽度只剩 `104 - 11*2 = 82`。`Row` 里**单位先按本征宽度占走**，剩下的才轮到
`Flexible` 的数字——四位数就开始截。

⚠️ **不能靠"调小一个固定字号"了事**：单位是多语种的，「星币」2 个全角、`Stars`
5 个半角、**「スターコイン」6 个全角**（13px 下约 78px，几乎占满 82）。三者宽度差一倍
多，挑不出一个四语种都放得下的固定值——**日文比报上来的英文还紧**。

## 变更内容

1. **套餐卡那一行**：`Flexible + ellipsis` 换成整行 `FittedBox(fit: BoxFit.scaleDown,
   alignment: centerLeft)` + `Row(mainAxisSize: min)`。放得下原样画、放不下按比例缩，
   **永远不会出现省略号**。这与紧挨着下面那行金额用的是同一套做法（那行 2026-09-08
   就已经是 `FittedBox` 了，本次只是把上面这行对齐过去）。
2. **单位基准 13 → 11、间距 4 → 3**（产品追加「Stars 也可以缩小点」）。`FittedBox` 本来
   就是整行等比缩放、单位一直跟着数字一起变小；调小基准的作用是**把位置让给数字**：
   单位窄一点 ⇒ 整行本征宽度小一点 ⇒ 需要的缩放比例小一点 ⇒ 最终画出来的数字更大。
3. **`_Amount` 同样修**（概览卡的余额 38px 与下方三格统计 20px 都用它）：同一个
   `Flexible + ellipsis` 写法、同一个多语种单位，日文下同样会截。`scaleDown` 只在放不下时
   才缩，所以常见位数下这三处观感不变。

## 关键决策

- **不再加宽卡片。** 104 是 2026-09-08 对齐小程序定下的，加宽会把那一轮重新推翻；
  而缩放能在不动几何的前提下满足「完整展示」。
- **不写死字号。** 见上面的多语种宽度差；写死等于在日文上留一个同样的坑。
- **`_Amount` 一并修**：用户只报了套餐卡，但那是同一页、同一根因、同一个改法，
  留着等于等下一次报障。

## 验证结果

- **本机没有 Flutter SDK**，`flutter analyze` / `flutter test` **未执行**。
- 静态自检：`star_coin_page.dart` 括号配平（与 HEAD 相比 Δ 为 0）；全文件复查确认剩下的
  两处 `TextOverflow.ellipsis` 都在**标签**上（`starAvailable`、`_AccountStat.label`），
  那是有意的 nowrap——标签折行会把下面的数字整体下沉，保留。
- 新增 `test/star_package_amount_no_ellipsis_test.dart`：量本征宽度，守三条与字体无关的
  结构性事实——改前的排版在四个语种下本征宽度都超过 82（所以必然截断）、等比缩放后放得
  进去、单位收窄确实让整行更窄。
  ⚠️ 用例里**刻意不断言任何绝对像素阈值**：`flutter_test` 用方块测试字体（每字宽 = 字号），
  那种数字只在真机字体下才有意义。

## 未完成项与风险

- **真机未验**：需在四个语种下各看一眼套餐卡（尤其**日文**，单位最长）确认 30000 完整显示
  且数字仍清晰；概览卡余额与三格统计也一并扫一眼。
- **同一行内不同档位的缩放比例不同**（1000 不缩、30000 要缩），所以并排的卡片数字大小会
  有细微差异。金额那行 2026-09-08 起就是这个行为，本次保持一致。产品若要求所有卡片字号
  绝对统一，需要另外定一个"按最大档位统一缩放"的方案，会比现在复杂。

# 首页设备卡：左侧圆环与右侧文字上下居中（2026-09-03）

> 状态：**已改**，⚠️ **未编译未真机**（本机无 Flutter SDK，`dart analyze` / `flutter test` 均未跑）
> 适用范围：**仅 App 端**，只动一个文件 `lib/src/features/home/presentation/home_widgets.dart`
> 对照仓库：`/pgdata/pg/dh/photo-album`（微信小程序）`pages/home`
> 需求原文：「现在首页，发现 IOS 端 设备轮播图内容，左侧的图标和右侧的文字没有上下居中对齐。」
>
> 🔶 **小程序不动**：那边的版式是这套尺寸的来源，本轮是 App 把照抄错的一层拆掉（见第二节）。

## 一、现象：偏的不是「对齐方式」，是被撑高的那个盒子

设备卡（`_ConnectedDeviceCard`）里是一行两列：

```
Row(                                  // crossAxisAlignment 默认 center
  Image.asset(home-device-thumb, 83×83)   // 左：圆环
  SizedBox(width: 16)
  Expanded(SizedBox(height: 110, child: Column(…)))   // 右：设备名/状态/电量
)
```

`Row` 的居中是对的、圆环也确实居中，问题在右列：**居中的是那个写死 110 的盒子，
而盒子里的 `Column` 是顶对齐的**，内容根本没有 110 那么高，多出来的全空在下面。

| 连接态 | 右列内容实高 | 盒子 | 盒内空档 | 内容中心相对卡中心 |
| --- | --- | --- | --- | --- |
| 已连接 | 20×1.2 + 9 + 12×1.2 + 11 + 26 = **84.4** | 110 | 25.6 | **偏上 12.8** |
| 未连接 | 20×1.2 + 9 + 12×1.2 + 22 + 26 = **95.4** | 110 | 14.6 | **偏上 7.3** |

卡片高度是按 `AspectRatio(654/298)` 随屏宽走的（375dp 上 ≈143.5、430dp 上 ≈168.6），
但**偏移量与屏宽无关**，恒等于 `(110 − 内容高)/2`。日常看到的是已连接态，也就是偏得最多的那一档。

⚠️ **这条与 iOS 无关**：卡内所有字号都写死了 `height: 1.2`，行盒高度＝字号×1.2，
两端逐像素一致；安卓上同样偏 12.8，只是这轮在 iOS 真机走查时被看出来。
文档如实记一笔，免得下一轮有人去找「iOS 专属分支」。

## 二、110 是哪儿来的：小程序那条 `min-height` 不能直接照抄

小程序 `pages/home/home.wxss`：

```css
.device-info {
  /* 已连接显示「电量行」、未连接显示更高的「连接蓝牙」按钮，两态内容高度不同。
     device-info 在卡片内垂直居中，高度不固定时切换连接态会重新居中，导致标题/状态文字上下跳动。
     固定最小高度(取较高的未连接态)让整块居中位置恒定，内容仍从顶部排布 → 文字位置稳定不跳。 */
  min-height: 220rpx;
}
```

`220rpx ÷ 2 = 110`，App 这行就是这么来的。**诉求（切换连接态时文字不上下跳）是对的，
但实现方式不能搬**：那是按 webview 的默认行高（`normal`≈1.4）量出来的高度，
而 App 把每一处 `line-height` 都写死成 1.2，同样的内容在 Flutter 里只有 169rpx —— 
盒子照抄了、内容却矮了一截，空档就露在下面，变成「右边整体偏上」。

## 三、改法：右列取内容高，「不跳」改由**两态等高**兜住

| | 改前 | 改后 |
| --- | --- | --- |
| 右列高度 | `SizedBox(height: 110)` 裹 `Column`（顶对齐） | `Column(mainAxisSize: MainAxisSize.min)`，由 `Row` 默认的 `center` 直接对齐**内容** |
| 状态行下方那条间距 | 已连接 `11` / 未连接 `22`，各写各的 | 两态共用常量 `_kCardMetaGap = 11`，且**提到 `if` 外面**只写一次 |

两处必须一起改，否则等于用「文字上下跳」换「居中」：

- 只把 110 拿掉、间距不动 → 两态内容 84.4 与 95.4 不等高，两者各自居中，
  连接成功那一刻设备名会下移 5.5，正是小程序注释里防的那件事。
- 两态间距统一后，**两态逐像素等高**：电量行高 26（电量图标 26×26，比 12×1.2=14.4 的文字高）
  与「连接蓝牙」按钮高 26（上下内边距各 7 + 内容 12）恰好相等，间距一致 → 都是 84.4。
  连接状态一变，设备名与状态行一个像素都不动 —— 比原来的「块高恒定」更硬，
  因为它不依赖任何一个量出来的常数。

顺带修掉未连接态那个 `22`：小程序 `.device-status` 的 `margin-bottom: 22rpx` 与
`.device-connect-btn` 的 `margin-top: 22rpx` 是**相邻兄弟**（`.device-info` 是普通块、不是 flex），
在普通流里**外边距合并**成一条 22rpx(=11)，不是 44rpx。App 原来写的 22 是把两条 margin 加了起来。

改完右列内容 84.4 与左侧圆环 83 几乎等高，两边上下沿基本齐平。

## 四、验证

- ⚠️ **未编译未真机**：本机无 Flutter SDK。合入前至少 `dart analyze`，再真机看四点：
  1. **已连接**：圆环的中心线与「设备名 + 已连接 + 电量」整块的中心线齐平；
  2. **未连接**：同样齐平，且「未连接」与蓝色按钮之间比改前近 11；
  3. **点「连接蓝牙」连上的那一瞬**：按钮换成电量行，设备名与状态行**不动**；
  4. 长设备名仍是单行省略号，窄屏（360dp）左右不粘连。
- **没有新增用例**：`_ConnectedDeviceCard` / `_kCardMetaGap` 都是 `home_widgets.dart` 的文件私有符号，
  没有可注入的入口，这块的几何不变量目前靠代码注释与本文档守（与 09-01、09-02 几轮首页版式改动同口径）。

## 五、取舍与风险

- **未连接态按钮离状态行近了 11**（22 → 11）。这是与小程序对齐的结果，不是副作用；
  若产品复看嫌挤，改 `_kCardMetaGap` **一处**、两态一起动，⚠️ **别只加未连接那边** ——
  两态不等高，「文字不跳」当场破功。
- **右列不再有固定高度**，反而更抗挤：改前内容一旦超过 110（系统字体放大约 1.3 倍以上）
  就在 110 的盒子里 `RenderFlex overflow`；现在的上限是卡片自身的高度（≈143 起），
  同样的放大倍数还有余量。
- 卡片本身的几何（654:298 的比例、24 圆角、`_CardGlass` 投影、`_kCardIconGap`、
  左侧圆环 83）**一个数都没动**，本轮只动右列的高度与那一条间距。

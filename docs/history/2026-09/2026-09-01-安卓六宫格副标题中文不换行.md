## 一、改什么

只动第二行文案（副标题 `.entry-desc`）的**安卓**字号，**标题、iOS 一个像素不动**。

| 端 | 改前 | 改后 |
| --- | --- | --- |
| iOS | 「两行放得下的最大字号」9 ~ 11 | **完全不变** |
| 安卓 | 同一个值 − 1（8 ~ 10），中文在 360dp 上折成两行 | 在此基础上**继续往下找「一行就装得下」的字号**（下限 8）；找不到就保持原值 |

上一轮给安卓统一减了一号，但那是**观感**上的一档，不是**几何**约束：
中文最长的一条约 7 个字身宽，360dp 屏上副标题可用宽只有 ≈65，
安卓落在 10 时要 ≈70 —— 差 5 个像素，于是「拍摄照片并投屏」被折成两行。
这轮把需求里的「保证中文不换行」写成算式本身的一条硬约束。

英文那句「英语二行可以展示完整」正是**兜底分支**：
"Generate images with AI" 一行怎么都放不下（8 号就要 ≈90 宽），
新加的这一步一路试空、原样返回上一轮的结果，所以**英文/日文与上一轮逐像素相同**。

## 二、改法（`home_main_view.dart`）

`_entrySubtitleFontSize` 由「一步」拆成「两步」，第二步只在安卓走：

```dart
// 第一步（两端共用，与上一轮完全一致）：两行放得下的最大字号，安卓再减一号
var result = base - delta;
for (var size = _entrySubtitleMaxFontSize; size > base; size -= 0.5) {
  if (fits(size, 2)) { result = size - delta; break; }
}
if (!isAndroid) return result;
// 第二步（仅安卓）：从第一步的结果继续往下找「一行就装得下」的最大字号
for (var size = result; size >= base - delta; size -= 0.5) {
  if (fits(size, 1)) return size;
}
return result;
```

量文字的那段抽成了 `_subtitlesFitInLines(...)`，两步共用（只差 `maxLines` 传 2 还是 1），
参数与卡片里那个 `Text` 完全同参 —— 含 `textScaler`，用户放大系统字体时照样准。

⚠️ 三处要点：

1. **第二步从第一步的结果起步往下试**，所以本轮**只会更小或不变**，不可能把字号顶上去。
2. **第二步返回量出来的字号本身，不再减一次 `_entrySubtitleAndroidDelta`**：
   起点已经是减过的值，再减一次就成了「小两号」。
   下限同样取 `基准 9 − 1 = 8`，安卓最终值仍恒在 8 ~ 10，与上一轮的取值范围一致。
3. **卡片里的 `maxLines` 仍是 2，没改成 1**：中文不换行靠「把字号选到能单行装下」，
   不靠砍行数 —— 砍成 1 行会把英文重新截成半句，正是 2026-08-31 那轮治好的毛病。

`_HomeTextStyles.entrySubtitle` 的基准 9 没动；
`_HomeEntryCard.subtitleHorizontalReserve` 上那句「副标题不参与字号计算、固定 9px」是
2026-09-01 上一轮起就已过期的注释，本轮一并订正（它现在是字号计算的可用宽度来源）。

## 三、各屏宽实测预期（副标题可用宽 = (屏宽 − 66) ÷ 3 − 33）

| 屏宽 | 可用宽 | 中文单行需要 | 改前（安卓） | 改后（安卓） |
| --- | --- | --- | --- | --- |
| 360dp（最常见） | 65 | ≤ 9.3 | 10，**折两行** | **9，单行** |
| 384 / 390dp | 73 / 75 | ≤ 10.4 / 10.7 | 10，本就单行 | 10，不变 |
| 412dp | 82 | ≤ 11.8 | 10，本就单行 | 10，不变 |

⚠️ **已知边界**：320dp 及更窄的屏（很少见）中文单行要 ≤7.4 号，跌破下限 8 ——
第二步试空，回落到上一轮的行为（10 号、两行），不再往下砸字号。
同理，用户把**系统字体调大**到中文单行放不下时也会回落成两行；
两种情况都只是「保持原样」，不会出现「...」。

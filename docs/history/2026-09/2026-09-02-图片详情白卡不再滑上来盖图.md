## 一、上一轮为什么没修干净

09-01 那轮做了三条：白卡顶＝图片底（去掉压图的 3vh）、大图高度封顶在「屏高 − 底部文字区」、
`cover` 改 `contain`。三条都对，但它们只保证了**静止那一帧**看得全 ——
版式本身没动：大图是 `Positioned` 垫在一个**整页** `SingleChildScrollView` 下面、自己不跟着滚，
白卡在滚动区里。那篇文档自己在「六、风险与取舍」最后一条也写了这个尾巴：

> 大图仍然**不跟着滚**：这套「白卡盖大图」版式没变，只是现在保证了静止时整张图看得全。

整页什么时候会可滚？白卡的内容超过预留的 `_kCardMinHeight = 210` 时。而 210 是按
「内边距 16 + **一行**标题 36 + 简介 11 + **两行**简介 45 + 让开按钮 98 ≈ 206」算的——
中文标题折成两行（标题行 36 → 55）或简介三行（45 → 67），就已经越过 210，整页立刻可滚，
手一划白卡就盖上来，盖住的那截**永远看不到**（大图不滚）。这就是反馈里的「还是被下方的内容遮挡」。

## 二、小程序为什么没这个现象

那边不是「白卡浮在大图上」，是**吃掉剩余高度**：

```css
.detail-body { min-height: 100%; }      /* 内容不足一屏时也铺满 */
.detail-card { flex: 1 1 auto; }        /* 白卡吃掉留白之外的全部高度 */
```

留白 + 白卡加起来正好等于滚动区高度，**常态下没有可滚距离**，白卡也就无从滑上来。

## 三、改法：整页不滚，白卡只滚自己内部

| | 改前 | 改后 |
| --- | --- | --- |
| 外层 | `Stack` + `Positioned(top:0, height: heroHeight)` 大图 + 整页 `SingleChildScrollView` | `Stack` + `Positioned.fill(Column(...))` |
| 大图 | `Positioned`，垫在滚动区下面 | `Column` 第一栏 `SizedBox(height: heroHeight)`，**不在滚动区里** |
| 让位 | `SizedBox(height: spacerHeight)`（= heroHeight） | 删掉——分栏天然接在图的下沿 |
| 白卡 | `Container(constraints: minHeight: cardMinHeight)` | `Expanded` + `Container`，内部套 `SingleChildScrollView` |
| 文字超长 | 整页滚 → **白卡盖住大图** | 只滚白卡内部，大图一像素不动 |

`heroHeight` 的算式一个字没改（`min(屏宽 × 真实比例, 屏高 − (_kCardMinHeight + 安全区))` + `BoxFit.contain`），
所以**静止时的版面与改前逐像素相同**；改的只是「能不能被滑上来盖住」。
`spacerHeight` / `cardMinHeight` 两个局部变量随之删除——白卡高度由 `Expanded` 吃剩余，
等价于小程序的 `min-height:100%` + `flex:1`，横图时照样铺到屏幕底部（09-01 修的那条不丢）。

两处配套：

- 白卡加 `clipBehavior: Clip.antiAlias`：内部滚起来后，文字不能从两个圆角外面冒出来。
- 白卡的 `padding-bottom` 仍是 `98 + 安全区`（让开贴底那颗浮着的「开始投屏」）。
  它现在落在滚动内容里，简介再长也是滚到按钮上方停住，不会从按钮底下穿过去。

## 五、取舍

- **「白卡从图上盖过来」这个交互没了**。设计稿原本是这个意思，但产品这轮点名不要遮挡，
  两者不可兼得，本轮取后者。
- 白卡内部可滚时，滚动条落在白卡范围内（不再是整页），观感上滚动区域变小了 ——
  这是「大图不被盖」的必然代价。

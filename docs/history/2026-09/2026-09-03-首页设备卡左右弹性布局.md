## 一、小程序原件：一行两个「内容宽」的孩子 + `space-around`

`pages/home/home.wxss`：

```css
.device-carousel {                 /* 654×298rpx，圆角 24px */
  display: flex;
  justify-content: space-around;   /* ← 这轮的主角 */
  align-items: center;
}
.device-orbit { width: 166rpx; height: 166rpx; }   /* 左：圆环，定宽 */
.device-info  { min-height: 220rpx; }              /* 右：没写 width */
.device-title { max-width: 320rpx; …ellipsis }     /* 名字最宽到这儿 */
```

两个要点：

1. **`.device-info` 没有 `width`**。它是 flex 项，`width:auto` ⇒ 用**内容宽**（fit-content），
   即「设备名 / 状态行 / 电量行(或按钮)」里最宽的那一条，且设备名被 `max-width: 320rpx` 封顶。
2. **`space-around` 把剩余空档摊成「外 1 : 中 2 : 外 1」**：每个孩子左右各分 `free/4`，
   于是两侧留白相等、中间是它的两倍，整组在卡内**水平居中**。

375dp 上（rpx÷2）实算一笔，已连接、名字「星宝相框」（4 字 ×20 = 80）：
卡宽 327 − 圆环 83 − 信息块 80 = **free 164** → 外 41 / 中 82 / 外 41。

## 二、App 偏在哪：空档被 `Expanded` 吃光了

改前是 2026-08-31 那轮留下的写法：

```
Padding(horizontal: 18)
  Row(                                  // 默认 MainAxisAlignment.start
    Image.asset(圆环 83)
    SizedBox(width: _kCardIconGap = 16)
    Expanded( Column(设备名/状态/电量) )   // ← 吃掉剩下的全部宽度
  )
```

`Expanded` 意味着**没有剩余空间可摊**，`MainAxisAlignment` 写什么都没用；
右列虽然宽，但列里 `crossAxisAlignment: start`，文字统统贴在这段宽度的左端。
375dp 上：左留白 18、圆环 18~101、文字 117~197、**右边空 118**——
就是需求里说的「左右的内容都偏左」。

| 屏宽 | 卡宽(屏宽−60) | 改前 左留白 / 中间 / 右留白 | 改后（名字 80） | 小程序（换算到同一卡宽） |
| --- | --- | --- | --- | --- |
| 360 | 300 | 18 / 16 / 103 | 45.5 / 91 / 45.5 | 同左 |
| 375 | 315 | 18 / 16 / 118 | 38 / 76 / 38 | 41 / 82 / 41（卡宽 327）|
| 390 | 330 | 18 / 16 / 133 | 41.75 / 83.5 / 41.75 | 同左 |

> 卡宽 = 屏宽 − 页内缩 48 − [`_kCardPeekGap`] 12。App 的卡比小程序窄 12（那条缝是
> `clipBehavior: Clip.none` 下相邻卡不贴死用的），所以同屏宽下摊出来的空档比小程序略小，
> **比例一致**。

## 三、改法

```
LayoutBuilder(                                     // 卡内不再加 horizontal: 18
  final infoMaxWidth = 卡宽 − _kCardOrbit − _kCardIconGap × 2;
  Row(
    mainAxisAlignment: MainAxisAlignment.spaceAround,   // ← 照抄 CSS
    Image.asset(圆环 _kCardOrbit = 83)
    ConstrainedBox(maxWidth: infoMaxWidth)             // 右列取内容宽，不再 Expanded
      Column(mainAxisSize: min, crossAxisAlignment: start)
        ConstrainedBox(maxWidth: _kCardTitleMaxW = 160) Text(设备名, ellipsis)
        Row(mainAxisSize: min)  状态行
        Row(mainAxisSize: min)  电量行  /  _HomeConnectButton
  )
)
```

四处配套，少一处就白改：

- **右列必须放弃 `Expanded`**：吃满就没有空档可摊，`spaceAround` 会退化成「贴左」。
- **列里每一行都要是内容宽**：两条 `Row` 补 `mainAxisSize: MainAxisSize.min`。
  Row 默认 `max`，会撑满上限宽 → 列宽恒等于上限 → 空档又被吃回去。
- **「连接蓝牙」按钮不再套 `Align`**：`Align` 在有界约束下会摊满（它只有给了 `widthFactor`
  或约束无界时才收缩），同样把列钉死在上限宽。列的 `crossAxisAlignment: start` 本就让
  按钮按内容宽靠左，`Align` 从来只是多余的一层。
- **卡内去掉 `horizontal: 18` 的内边距**：两侧留白改由 `spaceAround` 摊出来，与小程序同源；
  留着就成了「18 + free/4」，比小程序更靠里，且左右仍不等。

顺手给状态行的文案补了 `Flexible` + 单行省略号：右列上限比改前窄了 16，
把这条唯一没有兜底的长文案（日文「接続されていません」一类）从「可能横向溢出」变成省略号。

## 四、窄屏为什么不会再「贴到一起」

2026-08-31 那次把 `spaceAround` 换成写死间距，起因是当时右列还有一条 `maxWidth: 190`
的魔数：360dp 上 83 + 190 = 273 顶满 276 的可用宽，摊给中间的只剩 1.5px。

这轮的闸不在「间距」而在**信息块的宽度上限**：

```
infoMaxWidth = 卡宽 − 圆环 83 − 2 × _kCardIconGap(16)
⇒ 内容顶到上限时，free = 32，spaceAround 摊出的中间间距恰好 = 16
```

即中间间距**恒 ≥ `_kCardIconGap`**，再窄就先省略设备名，不去挤间距。

- 屏宽 ≥ 335dp：先顶到的是设备名自己的 160（小程序 `.device-title` 的 320rpx），
  中间间距 ≥ (300−83−160)/2 = **28.5**（360dp），够宽。
- 320dp 的小屏：`infoMaxWidth` = 145 先起作用，设备名从 160 收到 145（多几个字省略号），
  中间间距正好 16、两侧各 8。

## 六、取舍与风险

- **设备名短时，图标与文字之间会拉得很开**（375dp 上约 76）。这是 `space-around` 的定义、
  也是小程序线上的样子，不是副作用。若产品复看后想要「贴近一点」，
  正确的改法是换 `MainAxisAlignment.center` + 一条固定间距（那就是**有意偏离**小程序），
  ⚠️ 别去改 `_kCardIconGap`——它现在只是窄屏下限，改大只会更早触发设备名省略。
- **卡内两侧留白随设备名长度变化**：名字越长两侧越窄（free 越小）。两端同款行为。
- 卡片自身几何（654:298、24 圆角、`_CardGlass` 投影、圆环 83、`_kCardMetaGap` 11、
  设备名下 9）**一个数都没动**，本轮只动横向分配。

# AI 助手顶栏标题不跟语种变

> 文档类型：Historical Change Record
> 日期：2026-09-11
> 环境：SSH（本机无 Flutter SDK）
> 分支与起始版本：main / `e537c44`
> 范围：`lib/src/shared/l10n/app_l10n.dart`、`lib/src/features/ai/presentation/{ai_chat_page,ai_sessions_page}.dart`、`test/ai_new_chat_title_l10n_test.dart`
> 相关规则：`AI_CONTEXT.md` 第 11 条「User-visible text belongs in `AppL10n`」

## 现象

AI 助手页面顶部标题（例如「新对话」）不随语种变化：把 App 切到英文 / 日文，顶栏仍然显示
简体中文的「新对话」。

## 根因（两个，都要修）

### 1. 占位标题来自后端，是写死的简中

新建会话时**后端**把 `session.title` 填成简中「新对话」（要等首条用户消息入库才自动填成
消息前 20 字）。而 App 这边判断「这个标题是不是占位」时，拿的是跟着语种走的
`l10n.aiNewChat`：

```dart
final newChatTitle = AppL10n.of(context).aiNewChat;   // 英文环境 = 'New Chat'
final serverTitle = session.title.isNotEmpty ? session.title : newChatTitle;
if (serverTitle != newChatTitle || ...) { _sessionTitle = serverTitle; }
```

英文环境下 `'新对话' != 'New Chat'` ⇒ 这个占位被当成**用户自己起的标题**，原样画到顶栏上。

**连带第二个症状**：`_sendChat` 里「首条用户消息顶替占位」那处判断同样是
`_sessionTitle == newChatTitle`，同理失配 ⇒ 英/日环境下**发完消息标题也不会更新**，
中文占位一直挂着。会话列表 `_buildCard` 的 `row.title.isEmpty ? l10n.aiNewChat : row.title`
是同一个毛病，整列都显示中文。

### 2. `_sessionTitle` 存的是「已解析的字符串」，切语种不会重算

即使认出了占位，`_sessionTitle` 里存的也是**当时那个语种**的写法。用户在页面上切语种时，
顶栏画的还是切换前那一版——这是「没有根据语种动态变化」的另一半。

## 变更内容

**`AppL10n.isNewChatTitle(String?)`**（新增，静态）：空串 / null / 空白，或**任意语种下的
`aiNewChat`**，都算「还没起名」。实现是遍历 `AppLanguage.values` 逐个比对，而不是写死一张
四语种的表——将来改任何一个语种的 `aiNewChat`，判定自动跟上，不会漏掉某一种而重新长出
同一个 bug。

四处调用点改用它：

| 位置 | 改动 |
| --- | --- |
| `ai_chat_page` `_createSession` | 后端占位换成当前语种的写法；「别让占位盖掉已同步的首条消息」那条语义不变，只是判定改成跨语种 |
| `ai_chat_page` `_sendChat` | 首条用户消息顶替占位的判定改成跨语种 |
| `ai_chat_page` `initState` | 会话列表/深链带进来的标题若是占位，按「还没起名」处理（置空） |
| `ai_sessions_page` `_buildCard` / `_openSession` | 列表项显示当前语种的写法；占位不再往聊天页传 |

**`_buildHeader` 改为每次 build 按当前语种重新取**：

```dart
final title = _sessionId.isEmpty
    ? ''
    : (AppL10n.isNewChatTitle(_sessionTitle)
          ? AppL10n.of(context).aiNewChat
          : _sessionTitle);
```

`AppL10n.of(context)` 订阅了 `AppLocalizationsScope`（`dependOnInheritedWidgetOfExactType`），
语种一变本页就重建，标题随之重取。用户自己起的标题（首条消息）当然照原样画，不动。

## 关键决策

- **不改后端。** 占位是后端的实现细节，而且历史数据里已经存着中文；端上按「这是占位」
  识别并本地化，比要求后端按 header 返回多语种更稳，也不影响已有会话。
- **只有完全相等才算占位。** 用户首条消息可能恰好包含「新对话」三个字（如「新对话框怎么
  用」），子串匹配会把用户的真标题吞掉换成占位，已按用例固定。
- **判定放在 `AppL10n` 而不是 AI feature 内**：它本质是「这串文案是不是某个 key 的任一语种
  取值」，与 l10n 目录同源，放在一起才不会和 `aiNewChat` 的改动脱节。

## 验证结果

- **本机没有 Flutter SDK**，`flutter analyze` / `flutter test` **未执行**。
- 静态自检：四个改动文件括号配平（`ai_chat_page.dart` 有一处 `(`/`)` 不等是 **HEAD 就存在**
  的噪声，本次 Δ 为 +6/+6，持平）；AI 页面内 `Text('…中文…')` 硬编码扫描 **0 命中**，
  确认顶栏那串确实只能来自后端标题。
- 新增 `test/ai_new_chat_title_l10n_test.dart`：四语种占位都要认出来（含繁中由
  `toTraditionalChinese` 自动转换的「新對話」）、空/null/空白按未命名处理、用户标题不被吞、
  以及遍历 `AppLanguage.values` 保证改文案不会漏语种。

## 未完成项与风险

- **真机未验**：需在英文 / 日文 / 繁中下各走一遍「新建会话 → 顶栏 → 发首条消息 → 会话列表」，
  并在页面停留时切换语种确认顶栏当场跟着变。
- 历史会话里若存着**用户自己**起的、恰好等于某语种 `aiNewChat` 的标题（如用户把标题改成
  「新对话」），会被当成占位而显示为当前语种的写法。判定按完全相等已把误伤压到最小，
  这一种取舍是有意的。

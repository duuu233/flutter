只动一个文件：`lib/src/features/gallery/official/official_gallery_detail_page.dart`。

## 1. 白卡不再压住图片下沿

`spacerHeight = heroHeight - size.height * 0.03` → `spacerHeight = heroHeight`。

那 3% 屏高原是「白卡圆角压在图上」的设计稿画法，但压住的正是图片下沿 ——
产品这轮明确「下面的文字不许挡图」。现在白卡顶 = 大图下沿，严丝合缝。
（小程序那边同一条是 `.detail-spacer` 的 `− 3vh`，一并去掉。）

## 2. 整张图要看得全：大图高度封顶

大图是 `Positioned` 垫在滚动区**下面**、**不跟着滚**（往上滑只会让白卡盖住更多），
所以「一屏放不下的部分」＝**永远看不到**。原来长图的下半截就这么一直在屏幕外。

```dart
static const double _kCardMinHeight = 210;   // 底部文字区最少要留多高
final maxHeroHeight = size.height - (_kCardMinHeight + bottomInset);
final heroHeight = math.min(size.width * _heroAspect, maxHeroHeight);
```

`210` = 内边距 16 + 标题/收藏行 36 + 简介 11 + 两行 45 + 让开贴底按钮的 98 ≈ 206，取整。
与小程序 `--detail-card-min: 420rpx` 是同一笔账（420rpx 在 375pt 屏上正是 210）。

⚠️ 配套必须把 `fit` 由 `BoxFit.cover` 改 **`BoxFit.contain`**：封顶后盒子比例不再等于图片比例，
`cover` 会放大填满再裁掉两边 —— 那就把 2026-08-13「不裁图」的结论又推翻了。
没被封顶时（绝大多数图）两者逐像素相同。两侧空档由外层 `ColoredBox(0xFFDFE3E9)` 兜底，
与小程序 `.detail-hero { background: #dfe3e9 }` 同色，不是页面米色。

## 3. 顺带修掉「白卡停在屏幕中段」（**App 独有**）

白卡原来写死 `constraints: BoxConstraints(minHeight: size.height * 0.45)`。
横图时（图矮 → 留白也矮）白卡下沿会停在屏幕中段，底下露出一条页面米色、贴底按钮浮在那条米色上。

改成 `cardMinHeight = size.height - spacerHeight` —— 白卡永远铺到屏幕底部，
等价于小程序 `.detail-body{min-height:100%}` + `.detail-card{flex:1}` 的自动吃剩余高度。
小程序天然没有这个毛病，所以这条只在 App 侧。

## 4. 有意**不同步**的一条

小程序的留白还要减一个实测导航高度（`calc({{heroPad}}vw - {{navHeight}}px)`）：
那边大图从**屏幕顶端**起算、滚动区从**导航栏下沿**起算，差着一个导航栏（2026-08-21 修的断层）。
App 的大图与滚动区都在同一个 `Stack` 里、`Positioned(top:0)` 与 `SingleChildScrollView` 同起点，
**不存在这段差值**，别照抄。

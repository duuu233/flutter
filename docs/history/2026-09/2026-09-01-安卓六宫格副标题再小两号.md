> 适用范围：**仅 App 端、且只影响安卓**（`lib/src/features/home/presentation/`）
> 上一版：[2026-09-01 安卓六宫格副标题再降一号](2026-09-01-安卓六宫格副标题再降一号.md)
> 再上一版：[2026-09-01 安卓六宫格副标题中文不换行](2026-09-01-安卓六宫格副标题中文不换行.md)
> 需求原文：「现在安卓端的首页下面的六宫格的副标题再缩放一点吧，保证中文不换行。英语二行可以展示完整。副标题安卓端需要再小二个字号」
>
> 🔶 **小程序不动**：那边 `.entry-desc` 是 18rpx、按屏宽等比，本轮只是 App 安卓端的字号档位。

## 一、改什么

还是只动第二行文案（副标题 `.entry-desc`）的**安卓**字号，**标题、iOS 一个像素不动**。

| 端 | 改前 | 改后 |
| --- | --- | --- |
| iOS | 「两行放得下的最大字号」9 ~ 11 | **完全不变** |
| 安卓 | 前两步算出来的 8 ~ 10，再减 1 → 7 ~ 9 | 那两步之后**统一减 3**（1 + 2），**5 ~ 7** |

需求里「保证中文不换行、英语两行可以展示完整」两条**上一轮就已经是算式自带的不变量**
（第二步挑「一行装得下的最大字号」、第三步只做减法），本轮真正要动的只有最后那句
「再小二个字号」—— 所以改动就是把第三步那个差值从 1 加到 **3**，一行代码。

## 二、改法（`home_main_view.dart`）

`_entrySubtitleAndroidFinalDelta`：**1 → 3**（第四轮记 1 + 本轮再记 2）。

```dart
// 第一步（两端共用）：两行放得下的最大字号，安卓再减 _entrySubtitleAndroidDelta（=1）
var result = base - delta;
for (var size = _entrySubtitleMaxFontSize; size > base; size -= 0.5) {
  if (fits(size, 2)) { result = size - delta; break; }
}
if (!isAndroid) return result;                       // iOS 在这里就出去了
// 第二步（仅安卓）：从 result 继续往下试到「一行就装得下」
for (var size = result; size >= base - delta; size -= 0.5) {
  if (fits(size, 1)) { result = size; break; }
}
// 第三步（仅安卓）：本轮唯一的改动 —— finalDelta 由 1 变 3
return result - finalDelta;
```

三个出口（`available <= 0` 的兜底、iOS 的早退、安卓的正常出口）都没动结构，
`finalDelta` 在 iOS 上恒为 0，所以这一号数只落在安卓身上。

### ⚠️ 为什么仍然不是去调 `_entrySubtitleAndroidDelta`

与上一轮同一个理由，**把它从 1 调到 3 会让中文一个像素都不动**：

第二步挑的是「一行装得下的**最大**字号」，360dp 屏上那个最大值就是 9（≈63 宽 ≤ 65）。
调大第一步的差值只是把第二步的**起点**从 10 压到 8，往下试第一个命中的仍旧是那条几何上限
——结果成了「英文小两号、中文原地不动」，不是需求那一档。差值必须加在**两步都走完之后**。

| | 上一轮 | delta 改成 3 | 本轮（两步之后再减 2） |
| --- | --- | --- | --- |
| 中文 360dp | 8 | 8（**没变**） | **6** |
| 英文 360dp | 上一轮值 | −2 | −2 |

### ⚠️ 三条不变量仍然成立

1. **不会新增「...」**：第三步只做减法，而比「两行放得下的字号」更小必然还是两行放得下。
2. **中文不会重新折行**：比「一行放得下的字号」更小必然还是一行放得下。
3. **六张卡仍共用一个值**：减的是那个共用值本身。

`maxLines` 仍是 2、`_HomeTextStyles.entrySubtitle` 基准 9 仍没动、标题字号没动；
卡内高度只会更矮，不会撑破。

## 三、各屏宽实测预期（副标题可用宽 = (屏宽 − 66) ÷ 3 − 33）

中文最长一条「拍摄照片并投屏」约 7 个字身宽：

| 屏宽 | 可用宽 | 改前（安卓中文） | 改后（安卓中文） | 是否仍单行 |
| --- | --- | --- | --- | --- |
| 360dp（最常见） | 65 | 8 | **6** | 是（≈42 ≤ 65） |
| 384 / 390dp | 73 / 75 | 9 | **7** | 是 |
| 412dp | 82 | 9 | **7** | 是 |

英文/日文：第二步照旧一路试空，第三步把第一步的结果减 3 ——
仍是**两行完整展示、不出省略号**，只是整体比上一轮小两号。

⚠️ **已知边界（本轮值得复看真机的一条）**：
下限跟着从 7 降到 `基准 9 − 1 − 3 = 5`。360dp 上中文落到 **6**、
已经是设计稿 `.entry-desc`（18rpx ≈ 9）的三分之二，**偏小到需要产品在真机上确认可读**；
再往下要的话建议改口径（例如中文单行放宽成两行、或给副标题设一个绝对下限），
而不是继续往这个差值上加。窄屏（320dp）或用户放大系统字体时会落到下限 5，
中文回落成两行，但仍不出「...」。

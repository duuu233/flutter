# 星币购买：简中语种不支持 PayPal，点「立即购买」只提示不建单（2026-09-03）

> 状态：**已改**，⚠️ **未编译未真机**（本机无 Flutter SDK，`dart analyze` / `flutter test` 均未跑）
> 适用范围：**仅 App 端、且只影响安卓**（安卓 = PayPal；iOS 的 Apple 内购未接，购买按钮本就置灰）
> 需求原文：「安卓端在购买星币的时候，加一个逻辑判断，当用户是简中语种的时候点击 paypal 支付的时候，
> 给一个提示『暂不支持人民币付款，请切换其他语种进行支付』，并且不执行后面的逻辑了，简中用户不支持 paypal 支付」
>
> 🔶 **小程序不动**：那边是微信支付（`payType=1`），本来就收人民币，与这条限制无关
> （渠道按端分工见 [2026-08-27 安卓 PayPal 支付对接](../2026-08/2026-08-27-安卓PayPal支付对接.md)）。

## 一、改什么

确认购买页（`StarPurchasePage`）的「立即购买」：**当前语种是简中**时，弹一句
「暂不支持人民币付款，请切换其他语种进行支付」并**当场返回**。

| 语种 | 改前 | 改后 |
| --- | --- | --- |
| 简体中文 | 正常建单 → 跳 PayPal | **只弹提示，什么都不做** |
| 繁中 / English / 日本語 | 正常建单 → 跳 PayPal | **完全不变** |

⚠️ **只拦简中**。需求原文说的就是「简中用户不支持 paypal 支付」，繁中不在其列 ——
全 App 别处常把「中文」写成 `zh` 系两种一起算，照那个惯性改这里会顺手把繁中用户也挡在付款之外。

## 二、改法（三个文件 + 一条用例）

### 1. 口径收在一处：`StarPurchase.payPalBlockedFor`（`lib/src/features/star/star_purchase.dart`）

```dart
static bool payPalBlockedFor(AppLanguage language) => language == AppLanguage.zh;
```

判定放在购买链路的编排类里、不散在页面上，理由与 `StarPayType.forCurrentPlatform`
那条注释（「别在业务里按平台现写 if」）一样：**将来 PayPal 侧开通了人民币，只改这一个方法**。

### 2. 文案：`AppL10n.starBuyCnyUnsupported`（`lib/src/shared/l10n/app_l10n.dart`）

简中按需求原文**逐字**写。en/ja/繁中的译文实际看不到（那三种语种根本不会被拦），
补齐只是为了 `_pick` 的形参完整，万一将来拦截范围扩大，文案已经在了。

### 3. 拦截点：`_StarPurchasePageState._buy()` 的**第一步**（`star_purchase_page.dart`）

```dart
final l10n = AppL10n.of(context);

if (StarPurchase.payPalBlockedFor(l10n.language)) {
  AppToast.warn(context, l10n.starBuyCnyUnsupported);
  return;   // 蒙层、余额基线、建单、创建支付一步都不走
}

setState(() => _busy = true);
```

⚠️ **位置就是这条改动的全部要点，晚一步都不行**：

| 若把判断放在… | 后果 |
| --- | --- |
| `AppLoadingDialog.show` 之后 | 先闪一下「正在下单…」的全局蒙层再弹提示，像是失败而不是「不支持」 |
| `StarPurchase.start()` 里 | 已经读过一次余额基线、并且**已经建了单** —— 后台留下一张永远付不掉的待支付单，对账时全是垃圾 |

最后那条正是 iOS 那条「付不了就别建单」（`StarPayType.supportedOnThisApp`，见 `StarCoinApi.createOrder`
的注释）已经踩过的坑，这轮沿用同一个道理：**拦在建单之前**。

⚠️ 提示用 `AppToast.warn` 而不是弹窗：本页所有「这次买不成」的话（下单失败、拉不起 PayPal）
都从这个出口说，`_buy` 的 catch 分支也是它；只有「已取消支付」那种**终局结论**才用
`showAppNoticeDialog`。

### 4. 用例（`test/star_purchase_test.dart`）

新增一条，钉的是**拦截范围**（简中 true，繁中/英文/日文 false），不是文案。
页面那一层是 UI 交互，本文件的定位是「不依赖网络与平台的口径」，没有为它加 widget 测试。

## 三、用户看到什么

1. 简中用户进星币管理页 → 选套餐 → 进确认购买页：**页面照常可进、金额照常看得见**
   （PayPal 那张渠道卡也照旧画着，它是说明这一端走哪个渠道，不是可点的选项）；
2. 点「立即购买」→ 屏幕中央弹一句「暂不支持人民币付款，请切换其他语种进行支付」，停 3 秒；
3. 去「设置 → 语言」切成繁中 / English / 日本語，回到本页，购买流程一切照旧。

⚠️ **按钮没有置灰**。置灰的话用户看不到原因（iOS 那边是配了一句 `_ApplePendingNote` 说明才敢置灰的），
而这条限制的出路是「换个语种」，必须让用户点得到、听得见那句话。

## 四、验证

- ⚠️ 未编译未真机。合入前 `dart analyze` + `flutter test test/star_purchase_test.dart`。
- 安卓真机走查四种语种：
  - **简中**：点「立即购买」→ 只出提示、**不出蒙层**、不跳浏览器；再确认后台**没有新增待支付单**；
  - 繁中 / English / 日本語：从建单到跳 PayPal、回跳确认，与改前逐字相同；
  - 切语种后回到本页，提示随即消失（`AppL10n` 是 InheritedWidget，切语种整页重译）。
- iOS 不受影响（购买按钮本来就置灰，`_buy` 在更前面一步就返回了）。

## 一、改什么

还是只动第二行文案（副标题 `.entry-desc`）的**安卓**字号，**标题、iOS 一个像素不动**。

| 端 | 改前 | 改后 |
| --- | --- | --- |
| iOS | 「两行放得下的最大字号」9 ~ 11 | **完全不变** |
| 安卓 | 上一轮两步算出来的 8 ~ 10 | 在那个结果上**再统一减 1**，7 ~ 9 |

上一轮已经把中文治成单行（360dp 屏上落在 9），产品复看真机仍嫌偏大，
要的是**在当前结果上再退一档**——中文照旧单行、英文照旧两行完整，只是整体小一号。

## 二、改法（`home_main_view.dart`）

新增 `_entrySubtitleAndroidFinalDelta = 1`，在 `_entrySubtitleFontSize` 的**两步之后**作为第三步统一减掉：

```dart
// 第一步（两端共用）：两行放得下的最大字号，安卓再减 _entrySubtitleAndroidDelta
var result = base - delta;
for (var size = _entrySubtitleMaxFontSize; size > base; size -= 0.5) {
  if (fits(size, 2)) { result = size - delta; break; }
}
if (!isAndroid) return result;                       // iOS 在这里就出去了
// 第二步（仅安卓）：从 result 继续往下找「一行就装得下」的最大字号
for (var size = result; size >= base - delta; size -= 0.5) {
  if (fits(size, 1)) { result = size; break; }       // 改前是直接 return size
}
// 第三步（仅安卓，本轮新增）
return result - finalDelta;
```

第二步由 `return size` 改成 `result = size; break;`，这样两条出路（第一步的两行结果、
第二步的单行结果）汇到**同一个出口**，第三步只写一次。
`available <= 0` 那个兜底出口同样减（`base - delta - finalDelta`），
免得留下一个「不减」的角落。`finalDelta` 在 iOS 上恒为 0，所以所有出口都能无脑减。

### ⚠️ 为什么不是把 `_entrySubtitleAndroidDelta` 从 1 改成 2

那样**中文一个像素都不会动**，只有英文变小 —— 不是需求要的那一档：

第二步挑的是「一行装得下的**最大**字号」，360dp 屏上那个最大值就是 9（≈63 宽 ≤ 65）。
把第一步的差值调到 2，只是让第二步的**起点**从 10 降到 9，往下试第一个命中的还是 9。

| | 改前 | delta 改成 2 | 本轮（两步之后再减 1） |
| --- | --- | --- | --- |
| 中文 360dp | 9 | 9（**没变**） | **8** |
| 英文 360dp | 第一步结果 | −1 | −1 |

差值必须加在**两步都走完之后**，最终值才会稳定比上一轮小一号。

### ⚠️ 三条不变量仍然成立

1. **不会新增「...」**：第三步只做减法，而比「两行放得下的字号」更小必然还是两行放得下。
2. **中文不会重新折行**：比「一行放得下的字号」更小必然还是一行放得下。
3. **六张卡仍共用一个值**：减的是那个共用值本身。

`maxLines` 仍是 2、`_HomeTextStyles.entrySubtitle` 基准 9 仍没动、标题字号没动；
卡内高度只会更矮，不会撑破。

## 三、各屏宽实测预期（副标题可用宽 = (屏宽 − 66) ÷ 3 − 33）

中文最长一条「拍摄照片并投屏」约 7 个字身宽：

| 屏宽 | 可用宽 | 改前（安卓中文） | 改后（安卓中文） | 是否仍单行 |
| --- | --- | --- | --- | --- |
| 360dp（最常见） | 65 | 9 | **8** | 是（≈56 ≤ 65） |
| 384 / 390dp | 73 / 75 | 10 | **9** | 是 |
| 412dp | 82 | 10 | **9** | 是 |

英文/日文：第二步照旧一路试空，第三步把第一步的结果减 1 ——
仍是**两行完整展示、不出省略号**，只是整体小一号。

⚠️ **已知边界**：下限跟着从 8 降到 `基准 9 − 1 − 1 = 7`。
320dp 及更窄的屏、或用户把系统字体调大时会落到那里（上一轮是落到 8）；
那种情况下中文回落成两行，但仍不出「...」。

# 星币不足弹窗：显示当前余额 + 「去充值」

> 文档类型：Historical Change Record
> 日期：2026-09-18
> 环境：SSH 开发机
> 分支与起始版本：main / 60583c8
> 范围：`features/ai/presentation/ai_chat_page.dart`、`shared/l10n/app_l10n.dart`、
> `features/star/presentation/star_coin_page.dart`、`routes/app_routes.dart`
> 当前权威文档：`docs/integration/APP_VS_MINIPROGRAM.md`（AI 星宝 / 星币两行）

## 背景与目标

产品原话：「『星币不足…』这个弹框要优化一下，**先在合适的位置显示一下当前用户剩余的星币**，
再就是在『我知道了』按钮的右边加一个按钮『去充值』，点击跳转充值页面。」两端同步。

改动前 App 侧这张弹窗只有一颗「知道了」——注释里写的理由是「APP 侧还没有购买页」，
那是 2026-08-12 的事实；**2026-08-27 安卓已经接上 PayPal**，星币管理页就是充值页，
所以这条限制早就不成立了。

## 变更内容

1. **弹窗正文下面多一条余额带**（`_buildTokenBalanceBar`，走 `AppDialog` 的 `content` 通栏位）：
   左「当前余额」、右「N 星币」，浅橙底 + 橙色粗体数字，与小程序 `.confirm-balance` 同款。
2. **「知道了」右边补一颗「去充值」**：`showCancel: true`，左键（取消位）= 知道了、
   右键（确认位）= 去充值 → `Navigator.pushNamed(AppRoutes.starCoin)`，回来后重取一次余额。
3. **新增两条文案**（中/繁/英/日四态）：`aiTokenBalanceLabel`、`aiTokenGoRecharge`。
4. **`_loadTokenBalance` 读不到余额时不再把数字抹掉**：`AiToken.fetchBalance()` 在网络抖动 /
   后端 5xx 时返回 null（它自己也不会污染 `AiToken.cachedBalance`），原来照写不误。
5. **弹窗弹出来之前先把余额等回来**（`_guardAiDialogue` 里由 `unawaited` 改成 `await`）。

### 追加（同日，产品看完第一版后定）：「去充值」**直达套餐确认**

`Navigator.pushNamed(AppRoutes.starCoin, arguments: true)` → 路由把 `true` 传成
`StarCoinPage(autoOpenPurchase: true)` → 该页拉完套餐后自己 push [StarPurchasePage]。

- ⚠️ **不从聊天页直接 push 确认页**：那一页要一个具体的 `StarPackage`，而套餐列表
  （`getGoodsList`）是在星币管理页拉的；确认页 2026-08-28 起**刻意不自己再拉一遍**
  （同一份列表拉两次、两处各存一份选中态，是「选了 A 进来却按 B 建单」这类错的温床）。
- ⚠️ **返回栈里留着星币管理页**：用户想换一档，退一步就能换。
- ⚠️ `_autoOpened` 只兑现一次：`_load()` 在买完回来时还会再跑一遍，不记住的话用户会被
  反复推进确认页、退不出本页。
- 拉不到套餐（后端挂了 / 一档都没上架）就停在本页：余额和消耗规则照样看得见。

### 顺带对齐：默认选中的档位（App 第一档 → 第二档）

`_selectedIndex` 原来是 0，注释却写着「默认第一档，**与小程序 `index.js` 一致**」——
小程序那边写的是 `packages[1] || packages[0]`，**默认第二档**（设计稿高亮的、有赠送的主推档），
两端本来就差一张。

以前这只影响星币管理页上的高亮；现在「去充值」直接把用户带进确认页，**两端确认的就是不同的
套餐**了，所以就地对齐成第二档（只有一档时 `_load` 里的越界回落把它拉回第一档）。
🔶 这一条超出「加个按钮」的范围，但不改的话新动线两端表现不一致；要退回原样只需把
`_selectedIndex` 的初值改回 0。

## 关键决策

1. **iOS 不画「去充值」**。那一端整块星币模块是藏起来的
   （`StarPayType.moduleHiddenOnThisApp`，2026-09-18 用户口径），`AppRoutes.starCoin` 只返回
   兜底空页——给了按钮点过去是一片空白，比没有按钮更糟。所以 iOS 仍是单颗「知道了」，
   余额带照常显示（那是「AI 还能用多少」的信息，与能不能买无关，与 AI 会话页余额胶囊同一条口径）。
2. **等余额回来再弹，而不是先弹后刷**。弹窗是一次性构建的（`showDialog` 的 builder），
   后到的余额不会让它重绘；用户刚点了发送、本来就在等一次网络往返，再多等一次感觉不出来。
   🔶 与小程序的机制差异：小程序 WXML 绑 `tokenBalanceText`，`setData` 落地时弹窗自己就更新了，
   所以那边不必等——**两端用户看到的都是最新余额**，只是实现路径不同。
3. **读不到就保持上一次的数字，不显示 `--`，更不伪造 0**。0 和「没读到」对用户是两件事：
   有余额的人看到 0 会以为自己不能用了。真的从没读到过时才是 `--`。
4. **文案「去充值」与小程序对齐**：小程序那颗原名「去购买」，同轮改名，去处未变
   （都是星币管理页，套餐购买就在那一页上）。

## 验证结果

⚠️ **本机（SSH 开发机）没有 Flutter 工具链**：未 `pub get`、未 `dart analyze`、未 `flutter test`、
未编译、未真机。实际做到的：

- 借 `flowerpot/tools/` 的四个 Dart 静态自检跑 `lib test`（166 个文件）全绿；
- 括号 / 引号配平脚本对改动文件全绿。

新增 `test/ai_token_short_dialog_l10n_test.dart`（四语种文案齐备、英文不漏中文、
`displayBalance(null)=='--'`）——**没跑过**。

**小程序侧同口径的用例是真跑过的**：`node tests/*.test.js` 59 个文件全过，
其中 `ai-dialogue-guard` 新增两条（弹窗里的数字跟着账户接口走 / 接口失败时数字不被抹掉）。

## 未完成项与风险

1. iOS 上要确认那颗按钮**确实不出现**（`moduleHiddenOnThisApp` 用 `defaultTargetPlatform`，
   widget 测试可覆盖，但本轮没写 widget 用例、也没跑）。
2. 余额带的版式（与正文、按钮行的间距）没在真机上看过。
3. ✅ 已追加：「去充值」现在直达确认购买页（见上）。仍未做的是「按缺口智能选档」——
   现在带过去的是**默认档**（第二档），不是「刚好够补上缺口的那一档」。产品没提，先不猜。
4. 默认档位对齐（0 → 1）会改变**星币管理页本身**的初始高亮，不只是新动线；
   真机上要顺带确认一眼。

## 回滚或恢复

`_showTokenShortDialog` 里去掉 `content:` 与两颗按钮那三行、把 `_guardAiDialogue` 的 `await`
改回 `unawaited`，即回到单颗「知道了」。l10n 两条与 `_loadTokenBalance` 的空值守卫可以留着，
它们不依赖这张弹窗。

「直达套餐确认」单独回退：把 `pushNamed` 的 `arguments: true` 去掉即可（`autoOpenPurchase`
默认 false，星币管理页照常停在那一页）。默认档位回退：`_selectedIndex` 初值改回 0。

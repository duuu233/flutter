## 一、改什么

同一个类里三处，都在 `_HomeEntryCard`：

| | 改前 | 改后 | 对应小程序 |
| --- | --- | --- | --- |
| 图标边长 | `_iconSize = 48` | `_iconSize = **45**` | `.entry-icon` 96 → **90rpx** |
| 卡内横向对齐 | `CrossAxisAlignment.start`（左对齐） | `CrossAxisAlignment.**center**` | `.entry-card { align-items: center }` |
| 标题对齐 | 无（默认随文本方向） | `textAlign: TextAlign.center` | `.entry-name { text-align: center }` |

折算口径沿用卡里其余尺寸的老规矩——**rpx 折半**（375dp 基准，同一张卡的
`border-radius: 28rpx` → 14、`margin-bottom: 20rpx` → 10），所以 90rpx → 45。

## 二、版面上实际动了多少（390dp 屏）

卡宽由外层算出：`(390 − 24×2 页内缩 − 9×2 中缝) / 3 = 108`，卡高 `108 × 220/206 ≈ 115.3`，
内容宽 `108 − 10×2 内边距 = 88`。

**纵向**（整组一直是垂直居中，本轮没动这条）：

| | 内容组高 | 上下各余 |
| --- | --- | --- |
| 改前 | 48 + 10 + 18（标题 15×1.2） = 76 | ≈ 19.7 |
| 改后 | **45** + 10 + 18 = **73** | ≈ **21.2** |

缩掉的 3 自动摊进上下留白，**卡高与卡片比例 206/220 一个数都不用动**。

**横向**（这是本轮观感变化的大头）：

| | 改前（左对齐） | 改后（居中） |
| --- | --- | --- |
| 图标左边距 | 0 | `(88 − 45) / 2 = **21.5**` |
| 标题左边距（中文四字 ≈ 60 宽） | 0 | `(88 − 60) / 2 = **14**` |

图标和标题各自按自己的宽度居中，所以**两者不会左对齐成一条竖线**——这与小程序
`align-items: center` 的结果一致（那边也是图标按 90rpx、标题按文字宽各自居中）。

## 三、⚠️ 为什么居中不会把标题挤成省略号

这条值得单写，因为六宫格的标题字号是**算出来的**，很容易以为改对齐会牵动它。

[`_HomeMainView._entryTitleFontSize`](../../../lib/src/features/home/presentation/home_main_view.dart)
按「六条标题里最长的那条」反推一个共用字号，输入是
`available = cardWidth − _HomeEntryCard.titleHorizontalReserve`（= 左右内边距 10 + 10）。

`CrossAxisAlignment` 从 `start` 换到 `center`，**Column 给孩子的约束完全不变**：两者都属于
「非 stretch」，孩子拿到的都是松约束 `0 ~ 内容宽`，只是最后摆放的位置不同。于是：

- 标题能用的最大宽度还是 88，`titleHorizontalReserve` 不用改；
- 日文「マイアップロード」那条仍然压在 ≈11.5，**省略号阈值一个像素都没移**；
- 那套算式因此一行都没改（也不该改）。

`textAlign: TextAlign.center` 平时同样不产生位移——标题框是按内容宽收缩的，框和文字一样宽。
它只在**标题真的被截成省略号、文本框顶满 88** 的那一刻起作用：没有它，那一刻文字会忽然
变回左对齐，和旁边没截断的卡对不齐。

## 四、没动什么

卡片比例 `206/220`、圆角 14、`rgba(255,255,255,.55)` 底与那套阴影、左右内边距各 10、
图标到标题的 `SizedBox(height: 10)`、`_HomeTextStyles.entryTitle` 的字号基准 15、
`_entryGridGap = 9`、`kAiEntryEnabled` / `kGalleryEntryEnabled` 两个灰度开关——全部原样。

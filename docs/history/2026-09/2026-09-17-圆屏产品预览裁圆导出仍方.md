# 圆屏产品：预览裁成圆，导出仍是方的

> 文档类型：Historical Change Record
> 日期：2026-09-17
> 环境：SSH
> 范围：`lib/src/state.dart`（`DeviceItem.shapeType`）、`lib/src/features/cast/presentation/cast_preview_page.dart`
> 双端：小程序同日同口径已改（`docs/changes/2026-09-17-圆屏产品预览裁圆导出仍方.md`）

## 背景与目标

后台产品配置有一项「形状类型」（`shapeType`：**0 = 方形，1 = 圆形**，列表 / 详情接口都下发）。
核对发现 App 侧**完全没消费它**：`shapeType` 全仓只出现在 `_deviceFromJson` 上方那行「列出
swagger 出参」的注释里，`DeviceItem` 里没有这个字段，投屏预览的框固定是 20px 圆角矩形。

## 产品定稿（2026-09-17）

**预览裁成圆、导出还是方的。** 设备屏幕是圆的，方框四角那一圈本来就显示不出来，所以预览裁圆
才是所见即所得；帧数据仍按**方形矩阵**传（四角留白），导出一个字不改。

⚠️ 硬要求（产品原话）：**只在圆形的情况下改，千万别改动到现有方形的逻辑和代码。**

## 变更内容

### `lib/src/state.dart`

- `DeviceItem` 新增 `final int shapeType`，**可选参数、默认 0**——现有全部构造点一行都不用改，
  未下发 / 非法值一律当方形。
- 新增 `bool get roundScreen => shapeType == 1`。**只认 1**：形状枚举以后可能加值
  （圆角矩形之类），没实现的形状退回方形，绝不能因为「不等于 0」就当圆的把四角裁掉。
- `_deviceFromJson` 解析 `data['shapeType']`（`_asInt` 对缺失/非法回落 0 = 方形）。

### `lib/src/features/cast/presentation/cast_preview_page.dart`

- 新增私有 `_ScreenClip`：`round` 为真用 `ClipOval`，否则**原样**是
  `ClipRRect(borderRadius: circular(_kClipRadius))`——else 分支一个参数都没动。
- 两处换成它：展示层（当前格底图）与编辑层取景框。
- 编辑层那层 `DecoratedBox` 按形状分两份写：圆形 `shape: BoxShape.circle`，方形照旧
  `borderRadius: circular(_kClipRadius)`。⚠️ `BoxDecoration` **不允许** `shape: circle` 与
  `borderRadius` 同时给（断言直接抛），所以只能分两份，不能在一份里塞两个字段。
- 顺带把拖拽阴影抽成 `_kPickupShadow` 常量给两个分支共用；**数值与之前逐字节一致**，
  而且仍然只在 `_dragging` 时挂上（不是常驻）。

## 关键决策

- **没有动 `_deviceSize`，一个字都没动。** 它同时是①取景框比例②**导出画布尺寸**，
  而且和 BLE 图传下发的 `screenCode`（`device.screenType.code`）绑在一起。为了让圆更圆去改它
  就是改导出，正好撞在产品那条红线上。
- **由此带来一个已知限制**：框的比例来自 `_deviceSize` → `FrameProtocol.screenTypes`，
  那张表目前只有 3.7寸 480×720 / 5.89寸 680×960 两条**竖向矩形**（7.3寸是 0×0 占位）。
  所以在圆屏产品的屏型带着真实方形分辨率进那张表之前，`ClipOval` 裁出来是个**椭圆**而不是正圆。
  进表之后这里自然就对了，`_ScreenClip` 不用再改。⚠️ 这是**协议侧的数据缺口**，不是本轮能补的：
  屏型码和真实分辨率要设备/固件那边给。
- **导出不裁圆**：`_bake` 照旧 `Rect.fromLTWH(0, 0, outW, outH)` 铺满白底再画图，
  四角就是白的。这正是「方形矩阵 + 四角填白」。

  注释）均为 0。

  `_dragging` 判据全部一致；`grep` 确认导出相关代码（`_bake`、`drawRect`、`outW/outH`、
  `_deviceSize`）只在注释里被提到，实现零改动。
- 新增 `test/device_round_screen_test.dart`（**未运行**）：`shapeType` 1 → 圆、0 → 方、
  **默认值是 0**、以及「2/9/-1 这类没见过的值一律当方形」。
- 小程序侧同口径改动的用例**真跑通了**（`node tests/projection-round-screen.test.js`），
  两端判据一致，可作旁证。

## 未完成项与风险

- **圆屏产品的屏型没进 `FrameProtocol.screenTypes`**：在那之前 App 侧圆形产品会是椭圆框，
  而且导出画布尺寸也不对（会回落 5.89寸 680×960）。这条要设备侧给屏型码 + 真实分辨率。
  ⚠️ **不要绕过它去改 `_deviceSize`**。
- 真机上要看：圆形产品进投屏预览，框是圆的、长按拖拽时阴影跟着圆形走；
  **方形产品必须和以前一模一样**。
- 相册列表 / 首页的缩略图没有跟着裁圆（本轮只按产品说的动「预览页面的框」）。

## 回滚或恢复

revert 后无残留。
